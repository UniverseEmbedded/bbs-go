# GoAdmin运营后台方案

GoAdmin 在本项目中的定位是“可写运营后台”：用于执行账号与资格相关的管理动作，并保证可审计、可追溯、权限最小化。所有写入以 Go 服务端为权威执行点。

## 目标与边界

### 目标

- 用最小工程量提供可用的运营管理 UI
- 把关键运营动作收口到同一处，并统一审计日志
- 支持“按用例驱动”的后台能力：发码、资格切换、封禁与解封

### 边界

- GoAdmin 不承担登录认证中心职责，统一走 Go 服务端的 SystemUser 认证与权限
- GoAdmin 不直连外部系统（bbs-go、Koishi、客户端），只通过 Go 服务端内部模块调用

## 信息架构（页面清单）

| 页面 | 读/写 | 说明 |
|------|------|------|
| 用户列表 | 读 | 按 user_id/昵称/状态检索 |
| 用户详情 | 读 | 展示资料、资格状态、最近审计 |
| 资格管理 | 写 | 资格授予/撤销、原因与备注 |
| 邀请码管理 | 写 | 创建/禁用/回收/查看兑换记录 |
| 封禁管理 | 写 | 封禁/解封、期限与原因 |
| 审计日志 | 读 | 按 actor/request_id/action/时间筛选导出 |

---

## 权限模型（RBAC）

SystemUser 最小角色建议：

| 角色 | 能力 |
|------|------|
| viewer | 只读查看用户/资格/审计 |
| operator | 资格切换、邀请码、封禁解封 |
| admin | 系统配置与权限管理（谨慎开放） |

约束：
- 默认最小权限，敏感动作需要更高角色
- 所有写操作必须带 `request_id`，用于幂等与审计串联

---

## 审计日志契约

所有写操作必须落地到 `audit_log`（或等价表），字段至少包含：
- actor（SystemUser id）
- action（稳定枚举）
- target（user_id 或资源 id）
- request_id（幂等键）
- payload 摘要（脱敏）
- created_at

## 关键用例（作为里程碑验收驱动）

| 用例 | 期望 |
|------|------|
| 发放邀请码 | 邀请码可创建、可禁用、可查询兑换结果；审计可追溯 |
| 禁用资格 | 资格状态变化可见；登录/联机侧能按规则拒绝；审计可追溯 |
| 封禁/解封 | 封禁原因与期限可设置；解封后状态恢复；审计可追溯 |
