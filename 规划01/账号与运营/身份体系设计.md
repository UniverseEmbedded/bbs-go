# 身份体系设计

本文档定义系统的3类身份主体及其权限边界。

---

## 身份主体分类

| 主体 | 说明 | 典型场景 |
|------|------|----------|
| PlayerUser | 玩家 | 游戏用户，通过注册或OAuth登录 |
| SystemUser | 后台人员 | 运营、管理员，手动创建 |
| ServiceAccount | 机器人/脚本 | Koishi、定时任务、CI/CD |

---

## PlayerUser（玩家）

### 登录方式

| 方式 | 说明 |
|------|------|
| 账号密码 | 用户名 + 密码 |
| Google OAuth | 通过Google账号登录 |

### 权限范围

- 访问游戏核心功能
- 修改个人资料
- 绑定/解绑QQ
- 查看个人战绩

### 限制

- 受门禁规则约束
- 无法访问Admin API
- 无法查看其他用户敏感信息

### Token结构

JWT 结构以 [账号系统设计.md](./账号系统设计.md) 为准。示例：

```json
{
  "sub": "10086",
  "iss": "duel-auth-go",
  "type": "player",
  "iat": 1730000000,
  "exp": 1730000900,
  "user_id": 10086,
  "email": "player@example.com"
}
```

## SystemUser（后台人员）

### 登录方式

| 方式 | 说明 |
|------|------|
| 邮箱密码 | 后台专用，不接OAuth |

### 权限范围

- 访问Admin API
- 用户管理（查看、封禁、解封）
- 邀请码管理
- 审计日志查看
- 系统配置

### 创建方式

- 只能由已有SystemUser创建
- 或通过数据库初始化脚本创建首个账号

### Token结构

```json
{
  "sub": "1",
  "type": "system",
  "role": "admin",
  "iat": 1730000000,
  "exp": 1730000900
}
```

## ServiceAccount（服务账号）

### 认证方式

| 方式 | 说明 |
|------|------|
| HMAC签名 | 请求携带签名，服务端验证 |

### 典型用途

| 服务账号 | 用途 |
|----------|------|
| koishi-bot | Koishi机器人调用Bot API |
| cron-job | 定时任务执行 |
| ci-cd | CI/CD流水线部署 |

### 权限范围

- 只能访问特定API（按角色配置）
- 无法登录Web后台
- 无法访问游戏核心功能

### HMAC认证流程

```
1. 服务端为ServiceAccount生成密钥（secret）
2. 客户端构造签名字符串：method + path + timestamp + body_hash
3. 客户端用secret计算HMAC-SHA256签名
4. 请求携带：bot-id, timestamp, signature
5. 服务端验证签名和时间戳
```

### 请求示例

```
POST /api/v1/bot/outbox/pull
X-Bot-Id: koishi-bot
X-Timestamp: 1730000000
X-Signature: hmac-sha256签名值
```

## API分区

### Player API

| 前缀 | 说明 |
|------|------|
| /api/v1/player/* | 玩家专用API |

鉴权要求：PlayerUser token

### Admin API

| 前缀 | 说明 |
|------|------|
| /api/v1/admin/* | 后台管理API |

鉴权要求：SystemUser token

### Bot API

| 前缀 | 说明 |
|------|------|
| /api/v1/bot/* | 机器人专用API |

鉴权要求：ServiceAccount HMAC签名

## 权限对照表

| 功能 | PlayerUser | SystemUser | ServiceAccount |
|------|------------|------------|----------------|
| 游戏核心 | ✓ | ✗ | ✗ |
| 个人资料 | ✓（仅自己） | ✓（全部） | ✗ |
| 用户管理 | ✗ | ✓ | ✗ |
| 邀请码管理 | ✗ | ✓ | ✗ |
| 审计日志 | ✗ | ✓ | ✗ |
| Bot API | ✗ | ✗ | ✓（按角色） |

## 数据隔离

### users表

```sql
-- PlayerUser 和 SystemUser 共用 users 表，通过 user_type 区分
user_type = 'player'  -- PlayerUser
user_type = 'system'  -- SystemUser
```

### ServiceAccount独立表

```sql
CREATE TABLE service_accounts (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL UNIQUE,           -- koishi-bot, cron-job
    secret_hash TEXT NOT NULL,           -- HMAC密钥的hash
    roles TEXT NOT NULL,                 -- JSON数组：["bot:read", "bot:write"]
    status TEXT NOT NULL DEFAULT 'active',
    created_at INTEGER NOT NULL,
    last_used_at INTEGER
);
```

## 审计要求

### 必须记录的操作

| 操作 | actor_type | 说明 |
|------|------------|------|
| 登录 | player/system | 记录IP、设备 |
| 封禁用户 | system | 记录操作人、原因 |
| 生成邀请码 | system/bot | 记录来源 |
| Bot API调用 | service | 记录请求内容 |

### 审计日志格式

```json
{
  "actor_type": "system",
  "actor_id": 1,
  "action": "user.ban",
  "target_type": "user",
  "target_id": 123,
  "ip_address": "1.2.3.4",
  "payload": {"reason": "作弊"},
  "created_at": 1730000000
}
```

## 安全考虑

### 密码策略

| 项目 | PlayerUser | SystemUser |
|------|------------|------------|
| 最小长度 | 8 | 12 |
| 复杂度 | 字母+数字 | 字母+数字+符号 |
| 强制2FA | 可选 | 推荐 |

### 会话管理

- 单设备登录：可配置
- 异地登录提醒：推荐
- 强制登出：后台可操作

### ServiceAccount安全

- 密钥定期轮换（建议90天）
- IP白名单（可选）
- 请求频率限制
