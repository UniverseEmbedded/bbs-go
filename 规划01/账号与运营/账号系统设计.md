# 账号系统设计

本文档定义账号系统和内测资格管理的设计。

---

## 核心决策（v2）

| 决策项 | 选择 |
|--------|------|
| 用户主键 | 自增ID（非邮箱） |
| 数据库 | SQLite（先跑通，后续可迁PostgreSQL） |
| 登录方式 | 账号密码 + Google OAuth（其他OAuth冻结） |
| 门禁规则 | 必须在群1且不在群2 |
| 后台部署 | GoAdmin + PocketBase 并排部署 |

详见 [GoogleOAuth配置与审核指南.md](./GoogleOAuth配置与审核指南.md) 了解 Google OAuth 的审核要求与配置详情。

## 跨系统用户 ID 统一

### 核心原则

**Go 服务端的 `users.id` 是全局唯一用户标识**，所有子系统通过此 ID 关联用户。

### 统一认证架构

```
┌─────────────────────────────────────────────────────────────┐
│                    Go 服务端（认证中心）                    │
│                                                             │
│  users.id = 10086                                           │
│  JWT payload: { user_id: 10086, ... }                       │
└─────────────────────────────────────────────────────────────┘
                          │
          ┌───────────────┼───────────────┬─────────────┐
          ▼               ▼               ▼             ▼
   ┌─────────────┐ ┌─────────────┐ ┌─────────────┐ ┌─────────────┐
   │ 游戏客户端  │ │   bbs-go    │ │  星图系统   │ │ PocketBase  │
   │             │ │   (社区)    │ │   (官网)    │ │  (查看台)   │
   │ user_id:    │ │ user_id:    │ │ user_id:    │ │ user_id:    │
   │ 10086       │ │ 10086       │ │ 10086       │ │ 10086       │
   └─────────────┘ └─────────────┘ └─────────────┘ └─────────────┘
```

### 各系统用户 ID 使用方式

| 系统 | 用户 ID 来源 | 存储方式 |
|------|-------------|----------|
| 游戏客户端 | JWT 解析 | 内存会话 |
| bbs-go | JWT 解析（不接入 bbs-go 登录），首次访问幂等创建 | 本地 users 表（id 与 Go 服务端一致） |
| 星图系统 | JWT 解析 | 无本地存储 |
| PocketBase | 只读查看（可选投影同步） | 运营查看台（非权威数据源） |

后台与查看台的详细方案见：
- [GoAdmin运营后台方案.md](GoAdmin运营后台方案.md)
- [PocketBase集成方案.md](PocketBase集成方案.md)
- [后台与查看台验收清单.md](后台与查看台验收清单.md)

```json
{
  "sub": "10086",
  "iss": "duel-auth-go",
  "iat": 1730000000,
  "exp": 1730000900,
  "user_id": 10086,
```

### 数据关联层级

| 层级 | 关联程度 | 实现方式 | 示例 |
|------|----------|----------|------|

## 数据表设计（SQLite）

### 用户主档

```sql
CREATE TABLE users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_type TEXT NOT NULL DEFAULT 'player',  -- player | system
    status TEXT NOT NULL DEFAULT 'active',     -- active | suspended | banned
    display_name TEXT,
    avatar_url TEXT,
    ban_reason TEXT,
    ban_until INTEGER,
    created_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL,
    last_login_at INTEGER
);

CREATE INDEX idx_users_status ON users(status);
CREATE INDEX idx_users_type ON users(user_type);
```

### 登录凭证（credentials）

```sql
CREATE TABLE user_credentials (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL REFERENCES users(id),
    credential_type TEXT NOT NULL,  -- password | google_oauth
    identifier TEXT,                -- google_sub（OAuth用）
    email TEXT,                     -- 可选，非主键
    password_hash TEXT,             -- 仅password类型
    created_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL,
    UNIQUE(credential_type, identifier)
);

CREATE INDEX idx_credentials_user ON user_credentials(user_id);
```

### QQ绑定与门禁

```sql
CREATE TABLE user_qq_bindings (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL REFERENCES users(id),
    qq_number TEXT NOT NULL UNIQUE,
    in_group1 INTEGER NOT NULL DEFAULT 0,   -- 是否在群1（内测群）
    in_group2 INTEGER NOT NULL DEFAULT 0,   -- 是否在群2（大群）
    gate_ok INTEGER NOT NULL DEFAULT 0,     -- 门禁状态：in_group1 && !in_group2
    last_snapshot_at INTEGER,
    created_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL
);

CREATE INDEX idx_qq_user ON user_qq_bindings(user_id);
CREATE INDEX idx_qq_number ON user_qq_bindings(qq_number);
CREATE INDEX idx_gate_ok ON user_qq_bindings(gate_ok);
```

### 邀请码

```sql
CREATE TABLE invite_codes (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    code TEXT NOT NULL UNIQUE,
    token TEXT NOT NULL UNIQUE,             -- 用于邀请链接
    issued_to_qq TEXT,                      -- 目标QQ号
    issued_by_type TEXT NOT NULL,           -- system | bot
    issued_by_id INTEGER,                   -- system_user_id 或 bot_id
    created_at INTEGER NOT NULL,
    expires_at INTEGER,
    used_by_user_id INTEGER REFERENCES users(id),
    used_at INTEGER,
    status TEXT NOT NULL DEFAULT 'new',     -- new | used | revoked
    note TEXT
);

CREATE INDEX idx_invite_code ON invite_codes(code);
CREATE INDEX idx_invite_token ON invite_codes(token);
CREATE INDEX idx_invite_qq ON invite_codes(issued_to_qq);
```

### 会话

```sql
CREATE TABLE sessions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL REFERENCES users(id),
    session_id TEXT NOT NULL UNIQUE,
    device_id TEXT,
    ip_address TEXT,
    user_agent TEXT,
    created_at INTEGER NOT NULL,
    expires_at INTEGER NOT NULL,

```

## 门禁规则

### 硬规则

```
gate_ok(qq) := in_group1(qq) && !in_group2(qq)
```

### 状态转换

| 条件 | 用户状态 |
|------|----------|
| 未兑换 invite_token（或未绑定 QQ） | pending_invite（允许登录，但访问受限，需激活） |
| gate_ok = true | eligible（允许使用） |
| gate_ok = false | suspended（禁止使用） |
| 后台封禁 | banned |

### 受限态说明（pending_invite）

- 允许完成 OAuth/登录流程并获得“受限会话”，用于进入站内并完成激活
- 不允许访问需要内测资格/门禁的资源接口
- 通过兑换 `invite_token`（邀请码/邀请链接）完成绑定 QQ 与资格判定后，才进入 `eligible/suspended`

### 防误判策略

- 连续2次对账都显示不满足门禁才从 eligible → suspended
- 对"加入群2"可立刻触发 suspended（可配置）
- 提供申诉入口

## 登录流程

### 账号密码登录

1. 用户输入账号 + 密码
2. 服务端验证密码
3. 校验 gate_ok（门禁）
4. 若开启2FA：创建otp任务 → Koishi私聊发码 → 用户输入验证
5. 签发 access_token + refresh_token

### Google OAuth 登录（Web Flow）

OAuth 路由属于公网稳定入口，不带版本号：

- `GET /api/auth/oauth/begin/:provider`
- `GET /api/auth/oauth/callback/:provider`

迁移注记：

- 旧实现如存在 `/api/v1/auth/oauth/*`，应作为兼容别名保留一段时间；公网与第三方控制台配置以 `/api/auth/oauth/*` 为准。

#### A. begin（发起授权）

1. 用户点击 Google 登录，浏览器跳转到 `GET /api/auth/oauth/begin/google`
2. 服务端生成一次性 `state` 并绑定到服务端会话（必须有有效期与一次性消费约束）
3. 服务端重定向到 Google 授权页（携带 `client_id`、`redirect_uri`、`scope`、`state`）

`invite_token` 与首登规则：

- 创建玩家账号（首次注册）允许不携带 `invite_token`，但账号将处于 `pending_invite`（访问受限，需激活）
- 若 begin 阶段携带 `invite_token`（来自邀请链接），服务端必须把它与本次 `state` 绑定（不要把 invite_token 透传到第三方或写入 URL 日志）

#### B. callback（回调落地）

1. Google 重定向到 `GET /api/auth/oauth/callback/google?code=...&state=...`
2. 服务端校验 `state`（必须一次性、且与会话绑定；校验失败返回 `INVALID_STATE`）
3. 服务端用 `code` 向 Google 交换 access token，并拉取用户信息（至少包含 `sub` 与 `email`）
4. 服务端按 `google_sub` 查找用户凭证
5. 若找不到凭证：
   - 若本次 `state` 绑定了有效 `invite_token`：创建用户 + 绑定 QQ（从 invite_token 读取 issued_to_qq）+ 写入 Google 身份
   - 否则：创建用户 + 写入 Google 身份，账号状态为 `pending_invite`（不绑定 QQ），签发“受限会话”，并提示需要激活
6. 登录成功前必须校验门禁：对已绑定 QQ 的账号校验 `gate_ok(bound_qq)`，不满足返回 `SUSPENDED_BY_GATE`
7. 签发 `access_token + refresh_token`（`pending_invite` 的访问受限，直至激活）

#### C. 回跳与前端落地

OAuth callback 成功/失败都采用 302 回跳到站内页面进行提示与落地，不把 access_token/JWT 放在 URL query 中。

### OAuth 安全约束（最小集合）

- 必须使用 `state` 防 CSRF，且一次性消费
- 若支持 `redirect`：仅允许站内 path（或白名单），禁止任意外域，避免开放重定向
- 禁止把 token 放在 URL（query/hash），避免泄露到浏览器历史、日志与 Referer

### Token有效期

| 类型 | 有效期 |
|------|--------|
| access_token | 15分钟 |
| refresh_token | 7天 |

## 注册与激活流程

1. Koishi上报群快照，服务端计算可邀请候选
2. 服务端生成 invite_token，创建outbox任务
3. Koishi私聊发送邀请链接
4. 用户打开链接，选择注册方式（密码/Google）
5. 注册/首登时若携带 invite_token：绑定QQ（从invite_token获取），服务端二次校验 gate_ok，创建用户并签发token
6. 注册/首登时若不携带 invite_token：创建用户并进入 `pending_invite`（访问受限），提示用户后续激活

### 激活流程（补填邀请码/邀请链接）

1. `pending_invite` 用户在站内提交 `invite_token`
2. 服务端校验 invite_token 一次性/过期，并读取 `issued_to_qq`
3. 绑定 QQ，并二次校验 `gate_ok(issued_to_qq)`
4. 若门禁满足：状态迁移为 `eligible`；否则迁移为 `suspended`
5. 写审计日志（成功与失败都记录）

---

## QQ Bot 2FA流程

1. 用户密码登录成功
2. 服务端创建otp任务（outbox）
3. Koishi私聊发送一次性验证码
4. 用户输入验证码
5. 服务端校验验证码，签发token

### 验证码约束

- 有效期：5分钟
- 长度：6位数字
- 限流：同一用户每分钟最多3次

## API设计

### Auth API（玩家）

| 端点 | 方法 | 说明 |
|------|------|------|
| /api/v1/auth/register | POST | 注册（invite_token 可选；缺失则进入 pending_invite） |
| /api/v1/auth/login | POST | 登录（pending_invite 允许登录但访问受限） |
| /api/v1/auth/2fa/verify | POST | 2FA验证 |
| /api/v1/auth/refresh | POST | 刷新token |
| /api/v1/auth/logout | POST | 登出 |
| /api/v1/auth/validate | GET | 校验 access_token |

#### 请求兼容（字段）

- `POST /api/v1/auth/register` 支持 `invite_token`（推荐）与 `invitationCode`（兼容前端历史字段），语义相同，均表示邀请 token

### OAuth API（公网稳定）

| 端点 | 方法 | 说明 |
|------|------|------|
| /api/auth/oauth/begin/:provider | GET | 发起 OAuth 授权（仅 google 对外） |
| /api/auth/oauth/callback/:provider | GET | OAuth 回调落地 |

### Player API（资源）

| 端点 | 方法 | 说明 |
|------|------|------|
| /api/v1/player/profile | GET | 获取个人信息 |
| /api/v1/player/bind/qq | POST | 绑定QQ |
| /api/v1/player/activate | POST | 激活（兑换invite_token，解除受限） |

### User API（兼容）

| 端点 | 方法 | 说明 |
|------|------|------|
| /api/v1/user/profile | GET | 个人信息（Web前端历史接口；应与 player/profile 一致） |

### 错误响应（JSON 契约）

- 客户端约定：对非2xx响应会按 JSON 解析错误体，因此服务端错误响应必须返回 JSON，至少包含 `error`
- 推荐格式（用于可预期的错误码与字段提示）：
  - `code`：稳定的错误码（机器可读）
  - `message`：面向用户的错误描述
  - `error`：`message` 的兼容别名（前端可直接展示）
  - `fields`：字段级错误（可选）

### 错误码（节选）

| code | 场景 |
|------|------|
| INVALID_STATE | OAuth 回调 state 校验失败 |
| OAUTH_CODE_EXCHANGE_FAILED | OAuth code 换 token 失败 |
| ACTIVATION_REQUIRED | 已登录但账号未激活（pending_invite），需兑换 invite_token |
| SUSPENDED_BY_GATE | 门禁不满足，拒绝登录/续期 |
| PROVIDER_DISABLED | provider 冻结或未配置 |

### Admin API

| 端点 | 方法 | 说明 |
|------|------|------|
| /api/v1/admin/auth/login | POST | 后台登录 |
| /api/v1/admin/users | GET | 用户列表 |
| /api/v1/admin/users/:id/ban | POST | 封禁用户 |
| /api/v1/admin/invites | POST | 生成邀请码 |
| /api/v1/admin/audit | GET | 审计日志 |

### Bot API

|------|------|------|
| /api/v1/bot/qq/snapshot | POST | 上报群快照 |
| /api/v1/bot/qq/events | POST | 上报增量事件 |
| /api/v1/bot/outbox/pull | POST | 拉取任务 |
