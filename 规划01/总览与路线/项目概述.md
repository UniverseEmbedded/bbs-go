# 项目概述

## 背景

FAL的这个Duel小游戏太可惜了，它在国际上跟石沉大海一样（至少就我查资料来看是这样的，也许你需要查资料来求证一下），但是在taptap上它火的一塌糊涂（ https://www.taptap.cn/app/308052 ）

所以我现在准备给它改造一下。

## 产品线

本仓库包含游戏本体与天文层（由官网星图演进）的两条交付主线：

| 产品 | 说明 | 文档 |
|------|------|------|
| 几何决斗 | 跨端 1v1 对战游戏 | 本文档 |
| 天文层（星图基底） | 太阳系三维可视化 + 天文层可独立测试完成品 | [网站与星图/](../网站与星图/) 与 [开发流程里程碑.md](./开发流程里程碑.md) |

---

## 改造目标（几何决斗）

| 维度 | 目标 |
|------|------|
| 架构 | p5.js换成three.js+Troika Text，主要为了性能+3D+VR这三件事 |
| 平台 | 桌面，安卓，IOS，SteamVR+安卓VR |
| 功能 | 多人联机，本地双人，道具，皮肤 |
| 许可证 | 游戏本体CC BY-SA 3.0，其它全部AGPL |

## 原作来源确认

这个 Duel 的源头确实是 **FAL 在 OpenProcessing 上的草图**（sketch id 453716），并且 FAL 自己站点也有一页"Duel"介绍（2017 年发布，强调"简单 1v1 射击小游戏"并指回 OpenProcessing）。

至于"国际上石沉大海"，从这两处公开源头本身的传播量/讨论度来看，确实不像一个在海外社媒/论坛持续发酵的项目（更像"创意编程社区里的一份草图"）。

TapTap 这边则明显是"被移植/运营后在中文玩家圈集中爆发"的路径（TapTap 官方帖里也有人明确提到"从 OpenProcessing 移植到 LibGDX 并做了端适配"等）。

## 整体路线（已调整）

**核心变化：先分离后端，再做原型和本体开发。**

详细里程碑见 [开发流程里程碑.md](./开发流程里程碑.md)。

### 三段式里程碑

1. **里程碑A：分离后端** - 核心能在无渲染环境下跑起来，只吃输入、吐出状态
2. **里程碑B：本地双人** - 用最低成本逼出输入/状态/视角映射的成熟接口
3. **里程碑C：API文档** - 分离后立即写，基于后端契约

### 后续阶段

4. **里程碑I：天文层（完成品）**：以官网星图为基底推进荷载轨道物理、空间站、质量驱动器外观与 UI/UX
5. **里程碑J：工厂层（完成品）**：按规划14落地可独立测试的工厂层
6. **里程碑K：跨层接口**：天文层 ⇄ 工厂层 ⇄ 决头/地牢的协议与闭环验收

### 调整理由

- 把高耦合风险前置化解：先分离后端，换渲染或加VR都只是"表现层替换"
- 文档可以更早产出并更稳定：API文档基于后端契约
- 联机/双人是结构验证器：逼你把"输入→模拟→输出"闭环做到干净

## 服务端架构

```
┌─────────────────────────────────────┐
│                         客户端      │
│  (Tauri 桌面 / 移动端 / WebXR)      │
└─────────────────┬───────────────────┘
                  │
                  ▼
┌─────────────────────────────────────┐
│                    Go Web 服务端    │
│  - 静态网站托管                     │
│  - 账号/认证 API                    │
│  - 房间目录服务                     │
│  - 管理后台                         │
│  - LLM/代理等扩展服务               │
└─────────────────┬───────────────────┘
                  │
        ┌─────────┴─────────┐
        ▼                   ▼
┌─────────────────┐   ┌───────────────┐
│ Rust duel-server│   │ 本地 Koishi   │
│ (权威模拟)      │   │ + NapCat      │
│                 │   │ (QQ 机器人)   │
└─────────────────┘   └───────────────┘
```

### 组件职责

| 组件 | 职责 |
|------|------|
| Go Web 服务端 | 账号、认证、资格、房间目录、管理后台、静态站点 |
| Rust duel-server | 游戏权威模拟、tick 推进、快照广播 |
| 本地 Koishi/NapCat | QQ 群成员同步、邀请发放、资格检查执行 |

详见 [Go服务端集成方案.md](../账号与运营/Go服务端集成方案.md)
