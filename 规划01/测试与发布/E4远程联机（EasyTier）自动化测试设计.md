# E4远程联机（EasyTier）自动化测试设计

本文档为里程碑 E4“远程联机（EasyTier / 远程当 LAN）”提供可回归的自动化测试设计，目标是保证“我们自己的控制面与 UI 降级策略”稳定，不把 EasyTier/公网/OS 的不可控行为纳入 CI 失败源。

相关设计：
- 方案：[`规划01/联机与同步/EasyTier 远程当 LAN 方案.md`](../联机与同步/EasyTier%20远程当%20LAN%20方案.md)
- 总策略：[`规划01/测试与发布/自动化测试策略.md`](自动化测试策略.md)

---

## 范围与边界

### 目标（要自动化覆盖）

- 控制面状态机正确：启动/停止/失败/重试路径不撕裂，且幂等可重入
- UI 可解释与可降级：入口不可用时有稳定的 reason code 与提示策略，且允许停用第三方入口并回退到手动 wsUrl
- 可分享连接地址链路：能生成“可被对方访问”的 wsUrl 候选列表，并禁止只给出 `127.0.0.1`
- 排障与社区沟通：可导出 EasyTier 运行日志（并对敏感字段脱敏），结合 duel-server/客户端日志可定位问题

### 非目标（不做自动化断言）

- EasyTier 节点可用性（第三方服务、网络波动、地域差异）
- 公网打洞/中继成功率与性能（不可控、不可在 CI 稳定复现）
- VPN 网卡的真实枚举行为（OS/驱动差异大，仅做“输入→输出”的纯函数逻辑测试）
- “两台异地设备打一局”闭环（保留为手测脚本，但标准化日志采集物）

## 分层测试设计（Core / Adapter / E2E / 手测）

### 1) Core（可测）

Core 只做纯逻辑：给定“设置快照 + 平台事件序列”，输出“动作意图 + UI 状态 + 可解释错误”。

必须覆盖的自动化点：
- 状态机：`disabled -> starting -> running -> stopping -> disabled`；失败进入 `failed` 且可恢复
- 幂等：重复 start/stop 不产生重复副作用；失败后再次 start 行为稳定
- 事件乱序：`started/exited/error` 乱序到达时状态仍一致
- reason code：错误归因稳定，保证 UI 与日志采集能对齐同一套枚举

### 2) Adapter（薄封装，可测但用 Fake）

Adapter 负责平台差异（Tauri）：启动/停止 EasyTier、读取状态、导出日志、枚举网卡。自动化测试只验证：
- command 调用的参数构造与返回结构稳定
- 平台事件上报到 Core 的映射稳定
- 日志导出包含必要字段且脱敏规则生效

不做真进程、真网卡、真节点连接。所有外部输入用 Fake 注入。

### 3) E2E（半自动）

E2E 的目标是“UI 走通降级路径”，不要求真实节点可用：
- 切换入口列表策略（默认/清空/自定义）后 UI 状态变化正确
- 触发“模拟失败 reason code”时，提示文案与按钮可达（切换入口/停用第三方/导出日志）
- 复制分享 wsUrl：候选地址列表可选，且不出现仅 `127.0.0.1`

注：当前仓库尚未引入 Playwright/Cypress；E2E 先作为设计保留，等引入后再落地。

### 4) 手动测试（必须）

对齐 E4 验收标准的最小手测脚本：
- 异地两设备在 EasyTier 网络内完成一局对战
- 入口不可用时 UI 可解释并能切换入口或关闭第三方入口
- 一键导出 EasyTier 日志，且结合 duel-server 与客户端日志能定位问题

## reason code 规范（用于 UI、日志、测试断言）

reason code 要求：
- 稳定：不依赖具体错误字符串
- 可聚合：能把不同平台差异映射到同一类别
- 可操作：每个 reason code 都能给出明确的 UI 下一步动作

建议最小集合：
- `not_supported`：当前平台不支持（Web 端）
- `binary_missing`：EasyTier 程序不可用
- `spawn_failed`：启动进程失败（权限/路径/未知）
- `exited`：进程退出（无更细原因）
- `entry_unreachable`：入口不可达或解析失败（HTTP connector / DNS 等）
- `auth_failed`：网络名/密钥等认证失败
- `timeout`：关键阶段超时（启动/握手/获取地址）
- `unknown`：未归类错误（需附带原始错误信息用于排障）

## 可分享 wsUrl 的契约测试

Core 的纯函数应接受“网卡列表”（含多 IPv4/IPv6、loopback、虚拟网卡标记）并输出：
- 候选地址列表（含可读 label）
- 默认推荐项（稳定排序）

必须断言的规则：
- 禁止只输出 `127.0.0.1`
- 多网卡时排序稳定：优先 overlay 虚拟网卡 IPv4，其次局域网 IPv4，再次其它
- 无可用地址时提供明确提示与手动输入 wsUrl 的回退路径

---

## 日志导出与脱敏契约

导出包建议包含：
- 入口节点列表（是否启用第三方入口、当前选择）
- 最近 N 行 stdout/stderr（可配置 N）
- 核心状态机的状态变化时间线（含 reason code）
- 网卡枚举摘要（仅地址与类型，不含机器名等敏感字段）

脱敏规则（至少）：
- 网络名/密钥、token、密码字段必须脱敏（例如保留前后 2 位，中间用 `***`）
- 任何可能包含用户隐私的路径/用户名字段默认不写入，或写入前脱敏
