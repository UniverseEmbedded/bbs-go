# 发布与验收标准

本文档定义功能验收用例、测试矩阵和发布流程。

---

## 1. 功能验收用例

### 1.1 单机模式

| 用例 | 步骤 | 预期结果 |
|------|------|----------|
| 基础移动 | 按住方向键 | 玩家按方向移动 |
| 普攻发射 | 按下攻击键 | 发射箭矢 |
| 大招蓄力 | 按住大招键 | 蓄力条增加，松开发射 |
| 受击判定 | 被敌方箭矢击中 | HP 减少 |
| 死亡判定 | HP 归零 | 进入结算界面 |
| 暂停/继续 | 按 P 键 | 游戏暂停/继续 |

### 1.2 本地双人

| 用例 | 步骤 | 预期结果 |
|------|------|----------|
| 进入双人 | 选择双人模式 | 显示两个控制区域 |
| P1 控制 | P1 TFGH + Z/X | P1 正常操作 |
| P2 控制 | P2 方向键 + ,/. | P2 正常操作 |
| Ready 流程 | 双方普攻确认 | 3 秒倒计时后开局 |
| 竖屏翻转 | 手机竖屏双人 | P2 UI 180° 翻转 |
| 安全区 | 刘海/圆角区域 | UI 避开安全区 |

### 1.3 LAN 联机

| 用例 | 步骤 | 预期结果 |
|------|------|----------|
| 启动服务器 | P1 启动服务端 | 服务器运行，显示本机地址 |
| 创建房间 | P1 创建房间并设置识别码 | 房间出现在房间列表，识别码可复制 |
| 发现服务器 | P2 打开联机面板 | 在列表中发现服务器（或可手动连接） |
| 进入房间列表 | P2 进入该服务器 | 显示房间列表（含占槽/是否需识别码） |
| 加入房间 | P2 选择房间并输入识别码 | 成功加入，分配 P1/P2 槽位 |
| 对局同步 | 双方操作 | 画面同步 |
| 断线提示 | 一方断开 | 另一方收到提示 |
| 重新连接 | 断开后重新连接 | 回到房间列表，可重新加入房间 |

### 1.4 联机稳定性

| 用例 | 条件 | 预期结果 |
|------|------|----------|
| 正常网络 | 延迟 < 50ms | 体验流畅 |
| 高延迟 | 延迟 100-200ms | 可玩，轻微卡顿 |
| 弱网 | 5% 丢包 | 可玩，偶尔跳帧 |
| 极端网络 | 延迟 > 300ms 或丢包 > 20% | 提示网络差 |

说明：

- 联机稳定性测试可通过 Debug 网络模拟（延迟/抖动/丢包/乱序/重复/带宽，入站/出站可选）复现典型弱网条件。

### 1.5 自动更新（桌面端）

| 用例 | 步骤 | 预期结果 |
|------|------|----------|
| 无更新 | 打开“检查更新” | 提示“已是最新版本” |
| 有更新 | 打开“检查更新” | 提示有新版本，并给出更新与下载入口 |
| 更新失败兜底 | 模拟下载/校验失败 | 提示失败原因，并可一键打开下载页 |

## 3. 发布流程

### 3.1 版本号规则

采用语义化版本：`MAJOR.MINOR.PATCH+BUILD`

| 部分 | 说明 |
|------|------|
| MAJOR | 重大版本，可能不兼容 |
| MINOR | 新功能，向后兼容 |
| PATCH | Bug 修复 |
| BUILD | 构建号，内部使用 |

示例：`0.3.0+123`

### 3.2 发布前检查清单

#### 代码质量

- [ ] 所有测试通过
- [ ] 无 TypeScript 错误
- [ ] 无 ESLint 警告
- [ ] 回归测试通过

#### 功能验证

- [ ] 单机模式正常
- [ ] 本地双人正常
- [ ] LAN 联机正常
- [ ] 所有平台构建成功
- [ ] 桌面端自动更新入口可用（失败有兜底下载页）

#### 网站与接口验收（线上）

- [ ] `/api/v1/health` 返回 200
- [ ] `/privacy` 返回 200 且有正文内容（避免 404/空页）

#### 文档更新

- [ ] CHANGELOG 更新
- [ ] API 文档更新
- [ ] README 更新

### 3.3 发布渠道

| 渠道 | 平台 | 说明 |
|------|------|------|
| GitHub Releases | 全平台 | 主要发布渠道 |
| TapTap | Android | 国内移动端 |
| App Store | iOS | 待定 |
| Steam | 桌面 | 待定 |

### 3.4 灰度策略

1. **内测阶段**：仅内测群用户可玩
2. **公测阶段**：开放注册，限制人数
3. **正式发布**：全量开放

### 3.5 回滚策略

- 保留最近 3 个版本的构建
- 发现严重问题可快速回滚
- 回滚后发布修复版本

## 7. 崩溃收集

### 7.1 收集方式

- 桌面：Tauri 内置崩溃报告
- 移动端：系统崩溃日志
- Web：Sentry 或类似服务

### 7.2 关键指标

- 崩溃率 < 1%
- ANR 率 < 0.5%（Android）
- 无数据丢失

### 8.1 监控指标

| 指标 | 目标 |
|------|------|
| 日活用户 | - |
| 对局成功率 | > 95% |
| 平均对局时长 | - |
