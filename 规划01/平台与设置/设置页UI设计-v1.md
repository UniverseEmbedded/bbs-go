# 设置页 UI 设计 v1（独立面板 / 立即生效）

本文档定义“设置页 UI”的权威交互契约、字段覆盖范围、事件与生命周期要求。其目标是：严格约束实现，避免出现草稿/Apply 语义漂移，并保证跨平台一致性（Web/Tauri）。

相关参考：

- UI 原型（仅做视觉与信息架构参考，权威语义以本文为准）：`规划01/平台与设置/设置页UI原型.html`
- 设置系统原则与分类：`规划01/平台与设置/设置系统设计.md`
- 多开与 Profile 隔离：`规划01/平台与设置/调试多开与存档隔离.md`

---

## 1. 目标与非目标

### 1.1 目标

- 设置页为**独立面板**（非嵌入开始菜单面板）。
- 交互模型为**立即生效（Immediate-Apply）**：控件变更立即写入 SettingsStore 并由 Adapter 生效；不允许草稿层与“应用设置”按钮。
- 保留 **dirty（modifiedFromDefault）**：用于提示“当前设置与默认值不同”，并用于启用/禁用“恢复默认/重置分类”等按钮。
- 具备**保存状态**展示：saving/saved/error，明确区分“已修改默认值”与“持久化是否成功”。
- 能力探测与降级：不可用项必须禁用并给出解释与替代路径。

### 1.2 非目标

- 本文档不定义所有设置项的业务含义细节；业务含义以 `设置系统设计.md` 各分类与 Adapter 设计为准。
- 本文档不规定 UI 具体 CSS 细节（颜色/间距/字体），仅规定结构与交互语义。

---

## 2. 结构与布局（独立面板）

### 2.1 外观结构（必须）

- Overlay + Card 模态面板。
- Card 高度使用固定值（CSS 变量），内容区内部滚动：
  - 顶部 Header 固定
  - 主体为两列：左侧分类导航 + 搜索，右侧内容滚动区

### 2.2 导航与搜索（必须）

- 左侧分类列表（tablist），至少包含：
  - 通用、声音、联机、控制、图形、无障碍、数据、关于
- 搜索框：
  - 过滤左侧分类可见性
  - 过滤右侧设置项列表（按 label/description/keywords）

---

## 3. 交互语义（立即生效 + dirty）

### 3.1 立即生效（硬约束）

- UI 不维护草稿副本；任何有效变更都必须立即写入 `SettingsStore.persisted`。
- 不存在“未应用的修改”，也不存在“丢弃未应用修改并关闭”的流程。
- 设置面板关闭只影响 UI 可见性，不影响设置状态。

### 3.2 dirty 的定义（硬约束）

- `dirty` 在设置页 UI 中指：**modifiedFromDefault**（与默认值不同）。
- `dirty` 只用于：
  - 顶部提示“已修改默认值”
  - 启用/禁用“恢复默认”
  - 启用/禁用“重置本分类”
- 禁止把 `dirty` 用作“尚未应用”的语义。

### 3.3 保存状态（必须与 dirty 解耦）

设置页顶部状态区至少展示两类信息：

- **修改状态（dirty）**：`modifiedFromDefault: boolean`
- **保存状态（persistence）**：
  - `saving`：正在 debounce 或正在写盘
  - `saved`：最近一次写盘成功
  - `error`：写盘失败（必须可解释，并提供恢复建议）

UI 展示建议：

- `saved`：绿色
- `saving`：中性/黄色（不表示错误）
- `error`：红色，并显示简短错误原因

## 4. 控件事件到 Store 的映射（必须统一）

立即生效不等于“任何输入中间态都落盘”。本节定义统一策略，避免实现发散与性能风险。

### 4.1 写入 Store 的时机

- checkbox / switch：`change` 事件即写入 Store
- select：`change` 事件即写入 Store
- slider：
  - `input` 事件写入 Store（保证观感实时）
  - 数值输入框同步显示
- 文本输入框：
  - `blur` 或 `change` 才写入 Store（避免用户输入中间态造成频繁 sanitize）
  - 输入中允许临时无效值，但必须在提交时校验/修正

### 4.2 写盘节流（强约束）

- Store 的“内存态更新”可以高频；
- 持久化必须由统一 persistence 层 debounce（例如 250ms）负责；
- 禁止 UI 层自己决定“什么时候 save”，避免跨页面行为不一致。

---

## 5. Reset / 恢复默认（范围与确认规则）

### 5.1 全局恢复默认（必须）

- 行为：把 `persisted` 重置为默认值并立即生效。
- 要求：必须二次确认（危险操作）。
- 启用条件：`modifiedFromDefault === true`

### 5.2 分类重置（必须）

- 行为：只重置当前分类字段到默认值并立即生效。
- 启用条件：`modifiedCategories[category] === true`
- 二次确认策略：
  - 通用/音频/联机/控制/图形/无障碍：可无确认或轻确认
  - 数据清理类操作：必须确认

---

## 6. 能力探测与降级（必须可解释）

### 6.1 capability 展示规则

- 设置项存在不代表能力存在。
- 不可用时：
  - 控件禁用
  - 显示原因（“当前平台不支持”/“权限被拒绝”/“需要启用某能力”）
  - 若有替代路径，提供按钮入口（例如“打开系统设置”）

### 6.2 典型能力项（示例）

- WebRTC：探测 `RTCPeerConnection`
- 通知：Web 走 `Notification` 权限；Tauri 走 notification 插件能力与权限
- 托盘：仅桌面端；移动端不可用

---

## 7. 数据页（导入/导出/诊断包）的边界与脱敏

### 7.1 导出格式

- Web：
  - 导出 settings.json（仅设置）
  - 可选导出 zip（设置 + 回放/回归基线等）
- Tauri：
  - 导出 zip（设置 + profile 相关诊断内容）
  - 支持“打开配置目录 / 打开 profile 目录”

### 7.2 诊断包内容（建议标准化）

建议最小集合：

- `profiles/<profileId>/settings.json`
- 崩溃日志 / 运行日志（若存在）
- 回放与回归基线（若存在）

强约束：

- 不导出任何真实 token/密钥/个人身份信息
- 若日志可能包含敏感字段，必须脱敏

### 7.3 导入校验（强约束）

- 必须校验 `schemaVersion`
- 必须 sanitize（范围 clamp / 枚举兜底）
- 必须提供错误提示；导入失败不得覆盖原设置
- 导入模式至少支持：
  - replace：全量覆盖
  - merge：仅覆盖导入里出现的字段

## 8. 控制页（键位系统）落地要求（必须）

设置页的“控制/键位”不允许只做 UI 占位，必须完成闭环：

- 必须定义 Action 列表（按类别分组），并把输入设备映射到 Action，再生成 InputFrame。
- 必须支持：
  - 搜索过滤
  - 逐项重绑
  - 冲突检测与提示
  - 逐项重置 / 全局重置
  - 轴绑定（鼠标滚轮/手柄轴等）与阈值/死区（若使用）

键位系统的详细数据结构与事件流程必须在 `设置系统设计.md` 中以“输入映射”章节补齐（至少包含 Binding 结构与重绑生命周期）。

---

## 9. 生命周期（打开/关闭/订阅与资源释放）

### 9.1 设置面板生命周期

- open：
  - 读取 Store 当前 state 渲染 UI
  - 订阅 Store，反向同步 UI（只做展示同步，不写回）
- close：
  - 解除订阅与事件监听
  - 不做“保存/提交”行为（由持久化层自动完成）

### 9.2 系统事件与竞态合并（硬约束）

示例：系统主题变化事件

- 系统事件只能更新 `state.system.prefersDark`
- 只有当 `persisted.theme.themeMode === 'system'` 时，ThemeAdapter 才能用它决定 effective theme
- 禁止系统事件覆盖用户显式选择（light/dark）

---

## 10. 验收口径（建议写入测试用例）

### 10.1 语义验收

- 不存在“应用设置/未应用修改/丢弃未应用修改”。
- 修改任何设置：立即生效；关闭面板再打开，设置仍保持（持久化成功时）。
- dirty 只表示“与默认值不同”，并正确驱动“恢复默认/重置分类”的可用性。
- 保存失败必须可见且可解释（error 状态）。

### 10.2 功能验收（对齐信息架构）

- 分类导航、搜索过滤、右侧内容滚动均可用。
- 数据页：导入/导出/打开目录/导出诊断包具备可操作的真实实现或明确的禁用与解释。
- 控制页：键位系统闭环完成并可持久化。

### 10.3 多开验收

- 不同 profileId（DUEL_INSTANCE）之间设置互不污染。
