# 音频资源与打包策略

本策略用于统一音频资源的目录、许可口径、跨平台格式矩阵，以及“Web 端按能力选择格式”和“分平台打包不同内容”的工程约束。

---

## 目录约定

音频资源统一放在以下目录（作为源码与发行包的资源来源）：

- BGM：`duel-app/public/audio/music/`
- SFX：`duel-app/public/audio/sfx/`

路径约定（运行时引用）：

- `BGM_URL = /audio/music/<name>.<ext>`
- `SFX_URL = /audio/sfx/<name>.<ext>`

---

## 格式矩阵（ogg/mp3）

目标：在保证兼容性的前提下，尽量减少发行包体积。

建议矩阵：

- Web（通用浏览器）：`mp3 + ogg`
- Tauri 桌面（Win/macOS/Linux）：`ogg`
- Android（Tauri）：`ogg`
- iOS Safari Web：`mp3`

说明：

- `ogg` 作为主格式：体积与质量更优，桌面/安卓环境支持好
- `mp3` 作为兼容兜底：对 iOS/Safari 更稳

---

## Web 端选择策略（按能力与可用资源选择）

Web 端不得假设某种格式一定存在于发行包中，选择逻辑必须满足：

1. 若 `ogg` 可播放且资源存在，优先 `ogg`
2. 否则回退到 `mp3`
3. 若两者都不可用，则给出明确错误提示并在日志中记录 key 与候选 URL

实现可以采用以下任一口径：

- 走音频引擎的多 `src` 选择能力（例如同一音效 key 提供 `["...ogg", "...mp3"]`）
- 自行用 `HTMLAudioElement.canPlayType()` 做能力检测并构造 URL

---

## 分平台打包策略

### 背景

若在源码目录同时放置 `mp3 + ogg`，默认会导致所有平台产物都携带两份资源，Tauri 包体会被不必要地放大。

### 约束

- Web 产物需要 `mp3 + ogg`
- Tauri 产物默认只携带 `ogg`
- 允许通过构建参数切换（例如 Debug 产物可同时携带两份，便于排障）

### 推荐实现方式（工程方案）

采用“资源源目录 + 构建期拷贝到 public”的方式：

1. 资源源目录（不会直接进产物）：`duel-app/audio-src/{music,sfx}/...`
2. 构建前，根据目标平台拷贝到：
   - Web：`duel-app/public/audio/{music,sfx}/`（包含 mp3 + ogg）
   - Tauri：`duel-app/public/audio/{music,sfx}/`（只包含 ogg）
3. 构建完成后可选择清理临时拷贝，避免工作区长期混杂

该方案的关键点是：public 目录始终只包含“当前目标产物要打包的那份资源”。

## 旧版设计复用（game0003）

复用原则：

- 继续使用“静态资源表（key→候选 URL/默认增益）”
- 继续使用“进入菜单/对局前预加载核心 SFX”的节奏
- 播放触发在表现层通过快照差分完成，不把音频逻辑塞进核心模拟

典型触发（示例）：

- 短弓开火：检测箭列表新增 `shortbow`
- 长弓蓄力完成提示：检测 `chargedFrameCount` 跨过阈值的边沿
- 命中/受伤：检测 `damageRemainingFrameCount` 从 0→>0 或状态切换
