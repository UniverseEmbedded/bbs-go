# 设置系统设计

本文档定义设置系统的核心契约与架构设计。设置是跨层、跨平台的状态，必须通过统一的数据流和适配层去影响各模块。

---

## 核心原则

设置系统的“硬约束清单”以仓库根目录 [AGENTS.md](../../AGENTS.md) 的“设置系统契约”为准；本节用于解释原因并补充落地细则。

### 1. 单一事实来源：Settings Store 是唯一权威

- 所有设置只从 **SettingsStore** 读取（UI、渲染、音频、壳层都一样）
- 系统事件（系统主题变化、语言环境变化、音频焦点变化）**不能直接改业务**，只能先进入 Store（或通过 Adapter 产生 action）
- 禁止"某个模块自己缓存一份主题/语言/音量"然后慢慢不同步

> 否则你会遇到：UI 显示是深色，但 three 场景没切；通知仍是旧语言；音量 slider 对 BGM 无效等。

### 2. 设置必须是"声明式"并可迁移

- 每个设置项都要有：key、类型、默认值、合法范围、版本迁移（schema version）
- 永远不允许"读不到就随便 fallback 并写回"，要明确迁移策略

> 否则你一旦改 key/改枚举，会把用户配置搞坏，且难排查。

### 3. 传播规则必须统一：Store → 各子系统的"订阅适配器"

你需要把设置到子系统的生效路径固定成同一种模式：

- **ThemeAdapter**：把 theme token 同时喂给 CSS variables + three materials + Troika text
- **I18nAdapter**：把 locale 变化喂给翻译器、日期数字格式化器、字体 fallback 策略
- **AudioAdapter**：把 master/BGM/SFX 分组增益、mute、ducking 策略喂给音频引擎
- **TrayAdapter**：把"是否启用托盘""托盘菜单项"喂给壳层能力
- **NotifyAdapter**：把"是否启用通知""通知语言""通知偏好"喂给壳层能力
- **NetAdapter**：把地区/网络模式/延迟补偿/输入预测开关等喂给联机系统

> 重点是：模块不直接依赖平台/系统 API；只依赖自己的 Adapter 接口。这样你才能跨 Tauri/浏览器/移动端复用逻辑。

### 4. 能力受限必须优雅降级：设置项 ≠ 能力一定存在

- "托盘/通知/WebXR/某些音频能力"可能在不同平台不可用
- 规则必须是：**设置可以存在，但生效需要 capability probe；不可用时要有明确 UI 状态与回退行为**

> 否则你会出现"用户打开了托盘开关但平台根本不支持，系统沉默失败"的体验。

### 5. 热切换必须是原子且可重入的

- 热切换发生时：不能要求重启才能生效（除非你明确规定某些项需要重启，并在 UI 上写清楚）
- 必须定义"切换时的原子性"：一次切换里哪些东西必须同时更新（UI 文本、通知模板、字体策略、颜色 token）

> 否则会出现切换瞬间半屏中文半屏英文、或通知还用旧语言。

## 设置条目分类

### i18n（语言切换）

| 设置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| locale | string | 'zh-CN' | 当前语言 |
| fallbackLocale | string | 'en' | 回退语言 |

**Adapter 职责：**

- 把 locale 变化喂给 i18next 实例
- 触发日期/数字格式化器更新
- 触发字体 fallback 策略更新（中文需要不同字体）

**能力探测：**

- 无平台限制

### 主题/配色

| 设置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| themeMode | 'system' \| 'light' \| 'dark' | 'system' | 主题模式 |
| accentColor | string | '#00ff88' | 强调色（可选） |

主题 token 清单与 light/dark 调色板的权威值见：

- [配色与主题系统.md](../渲染与vr/配色与主题系统.md)

**Adapter 职责：**

- 监听系统主题变化（Tauri: `tauri://theme-changed`，Web: `matchMedia`）
- 把 theme token 同时喂给：
  - CSS variables（`--bg`, `--fg`, `--accent` 等）
  - three.js 场景（材质参数/雾/背景）
  - Troika Text 材质/颜色

**能力探测：**

- 无平台限制

### 托盘与通知

| 设置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| trayEnabled | boolean | true | 是否启用系统托盘 |
| notificationEnabled | boolean | true | 是否启用系统通知 |
| notificationSound | boolean | true | 通知是否播放声音 |

**Adapter 职责：**

- TrayAdapter：创建/销毁托盘图标，更新菜单项
- NotifyAdapter：请求权限，发送通知，处理点击回调

**能力探测：**

- 托盘：桌面端支持，移动端不支持
- 通知：需要运行时请求权限，可能被用户拒绝

**降级策略：**

- 平台不支持时：设置项显示为禁用状态，UI 提示"当前平台不支持"
- 权限被拒绝时：设置项显示警告，提供"打开系统设置"按钮

### 音频

| 设置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| masterVolume | number | 1.0 | 主音量 (0-1) |
| bgmVolume | number | 0.8 | BGM 音量 (0-1) |
| sfxVolume | number | 1.0 | 音效音量 (0-1) |
| uiVolume | number | 1.0 | UI 音效音量 (0-1) |
| muted | boolean | false | 是否静音 |

**Adapter 职责：**

- 管理 Howler 实例的生命周期
- 实现分组音量控制（BGM/SFX/UI）
- 实现 ducking（播放 UI/语音时压低 BGM）
- 处理移动端音频解锁（用户交互后才能播放）

**能力探测：**

- 所有平台都支持 WebAudio/HTML5 Audio
- 移动端有 autoplay 限制，需要用户交互后解锁

### 联机

| 设置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| region | string | 'auto' | 地区/服务器选择 |
| networkMode | 'auto' \| 'websocket' \| 'webrtc' | 'auto' | 网络模式 |
| latencyCompensation | boolean | true | 是否启用延迟补偿 |
| inputPrediction | boolean | true | 是否启用输入预测 |

**Adapter 职责：**

- 管理连接状态（连接/断线/重连）
- 实现延迟补偿与输入预测逻辑
- 处理房间/匹配相关逻辑

**能力探测：**

- WebSocket：所有平台支持
- WebRTC：需要探测 `RTCPeerConnection` 是否可用

### 输入映射

| 设置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| inputMapping | object | {} | 自定义按键映射 |
| gamepadEnabled | boolean | true | 是否启用手柄 |
| aimAssist | boolean | true | 是否启用瞄准辅助（VR） |

**Adapter 职责：**

- 归一化不同输入设备（键鼠/触屏/手柄/VR 控制器）
- 把输入映射到统一的 `InputFrame` 结构

**必须补齐的“键位系统数据结构”（权威要求）：**

- 必须存在 Action 列表（按类别分组），作为 inputMapping 的键空间（禁止直接用“某个 keyCode 字符串”作为业务语义）。
- inputMapping 的值必须能表达至少以下绑定类型：
  - keyboard key（可选：组合键）
  - mouse button / wheel（若使用）
  - axis（滚轮或手柄轴，含方向与阈值/死区，若使用）
- 必须定义冲突检测规则与提示策略（同键多动作、同动作多绑定等）。
- 必须定义“重绑生命周期事件”：
  - 开始重绑（目标 action）
  - 捕获输入（键/轴）
  - 冲突提示与用户决策（替换/取消）
  - 保存到 SettingsStore（立即生效）

### 画质

| 设置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| qualityPreset | 'low' \| 'medium' \| 'high' \| 'auto' | 'auto' | 画质档位 |
| shadows | boolean | true | 是否启用阴影 |
| postProcess | boolean | true | 是否启用后处理 |
| particleDensity | number | 1.0 | 粒子密度 (0-1) |
| fpsCap | number | 120 | FPS 上限（30-240） |
| vsync | boolean | true | 是否启用 VSync（桌面端为主） |

**Adapter 职责：**

- 根据 qualityPreset 调整 three.js 渲染参数
- 在 VR 模式下自动降级（保证帧率）

### 辅助功能

| 设置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| reducedMotion | boolean | false | 减少动画 |
| highContrast | boolean | false | 高对比度模式 |
| colorBlindMode | 'none' \| 'protanopia' \| 'deuteranopia' \| 'tritanopia' | 'none' | 色盲模式 |
| uiScale | number | 1.0 | UI 缩放（0.75-1.5） |

**Adapter 职责：**

- 调整动画/过渡效果
- 调整颜色方案

## SettingsStore API（最小权威接口）

本节约束 SettingsStore 对外可用的最小 API 与语义，避免不同模块自行约定导致发散。

### 状态结构（建议）

- `persisted`：用户设置（可迁移、可持久化）
- `system`：系统探测态（不持久化，例如系统深色偏好）
- `capabilities`：能力探测结果（不持久化）
- `persistence`：持久化状态（saving/saved/error），与 dirty 解耦
- `derived`：派生状态（modifiedFromDefault / modifiedCategories）

### 动作语义（必须）

- UI 的任何有效设置变更都必须立即写入 Store（立即生效），禁止草稿层与“应用设置”模型。
- 持久化必须在 persistence 层 debounce，UI 不得自行决定何时 save。

### 事件/竞态合并（必须）

- 系统主题变化等系统事件必须经 Adapter → Store。
- 系统事件不得覆盖用户显式选择：
  - `themeMode !== 'system'` 时，系统主题变化只能更新 system 状态，不得写入 persisted.themeMode。

## 测试策略

### 单元测试（可自动化）

- SettingsStore 的 action 处理与状态派生
- 各 Adapter 的"响应逻辑"（mock 平台 API）
- Schema 校验与迁移逻辑
- 默认值合并策略

### E2E 测试（半自动）

- 切主题后关键 UI 元素颜色变化
- 切语言后关键页面文本更新
- 设置持久化（重启后仍保留）

### 手动测试

- 各平台托盘/通知真实行为
- 移动端音频解锁流程
- VR 模式下的设置 UI 交互

## AGENTS.md 应该约束的内容

权威清单以 [AGENTS.md](../../AGENTS.md) 的“设置系统契约”为准。

本设计文档只补充落地细则：

- i18n/theme/audio/tray/notify 必须通过各自 Adapter 生效
- capability probe 与回退规则必须实现；不可用时 UI 必须可解释
- 热切换必须原子且可重入；明确哪些设置需要重启、哪些不需要
