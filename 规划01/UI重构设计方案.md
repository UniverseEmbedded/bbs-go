# UI 重构设计方案：从“工具栏”到“游戏大厅”

> 基于用户反馈：
> 1. 废弃左上角平铺按钮布局，改用**屏幕居中/左侧竖幅菜单**。
> 2. **单人游戏**为一级入口；**双人与联机**折叠进“多人游戏”二级入口。
> 3. **联机大厅**改为全屏独立界面，而非弹窗。

## 1. 核心交互流程重构

目前的 UI 是“单页应用+弹窗”模式，所有功能都在战斗界面（HUD）上。
新方案将 UI 分为三个明确的**场景（Scene）**，通过状态机切换：

```mermaid
graph TD
    A[启动游戏] --> B[主菜单场景 (Home)]
    
    subgraph Home [主菜单 (居中/左侧竖幅)]
        B1[单人游戏]
        B2[多人游戏] --> C[多人模式选择]
        B3[设置/关于]
    end

    subgraph Multiplayer [多人模式选择]
        C1[本地双人]
        C2[局域网联机] --> D[联机大厅场景 (Lobby)]
    end

    subgraph Game [战斗场景 (In-Game)]
        E[战斗 HUD]
        F[暂停菜单 (Esc/P)]
    end

    B1 -->|点击| E
    C1 -->|点击| E
    D -->|加入/开始| E
    E -->|结束/退出| B
```

## 2. 界面布局详细设计

### 2.1 主菜单 (Home Screen)
**布局**：
- **位置**：屏幕左侧竖幅（占宽 30%）或 屏幕正中卡片。
- **背景**：保留 3D 场景或动态背景，但被 UI 遮挡区域需虚化。
- **一级导航按钮**（大尺寸、竖排）：
  1. **单人速玩 (Single Player)** —— *高亮/默认焦点*
  2. **多人对战 (Multiplayer)** —— *点击展开二级菜单*
  3. **设置 (Settings)** —— *音量、画质、调试*
  4. **关于 (About)**
- **状态栏**：
  - 右上角/右下角：版本号、用户 ID（如有）。

### 2.2 多人游戏子菜单 (Multiplayer Submenu)
**交互**：点击“多人对战”后，在主菜单旁滑出，或替换主菜单内容。
**二级导航按钮**：
  1. **本地双人 (Local Dual)** —— *同屏对战*
  2. **局域网联机 (LAN Online)** —— *进入全屏大厅*

### 2.3 联机大厅 (Full-screen Lobby)
**布局**：全屏 UI，类似传统 FPS 游戏大厅。
- **顶部**：
  - 标题：“局域网联机”
  - 状态：连接状态、本机 IP、昵称设置。
- **左侧/中间**：**房间列表 (Server Browser)**
  - 列表项：房间名 | 模式 | 人数 | 延迟 (Ping) | 状态
  - 操作：点击条目 -> 右侧显示详情 -> 加入。
- **底部/右侧操作区**：
  - **快速加入**
  - **创建房间**（Host）
  - **刷新列表**
  - **返回主菜单**

### 2.4 战斗 HUD (In-Game HUD)
**设计目标**：极简，零干扰。
- **移除**：所有模式切换按钮（单人/双人）、帮助按钮、关于按钮。
- **保留**：
  - **状态**：血条、弹药、比分（仅在战斗进行时显示）。
  - **虚拟摇杆**：仅在触摸模式显示。
  - **暂停按钮**：右上角小图标（或按 ESC），点击唤出“暂停菜单”。
- **暂停菜单 (Pause Menu)**（模态弹窗）：
  - 继续游戏
  - 查看出招表 (Help)
  - 退出战斗 (返回主菜单)

## 3. 技术实现路径 (Roadmap)

### 3.1 状态机改造 (InputController)
目前的 `InputController` 混杂了 UI 逻辑与输入逻辑。需引入明确的 `UIPhase`：

```typescript
type UIPhase = 
  | 'home'          // 主菜单
  | 'multi_select'  // 多人选择
  | 'lobby'         // 全屏联机大厅
  | 'loading'       // 加载中
  | 'hud'           // 战斗中
  | 'pause';        // 暂停
```

### 3.2 DOM 结构分离
在 `ui.ts` 中，将 `#game-root` 下的子元素按层级重组：

```html
<div id="game-root">
  <!-- 3D/2D 渲染层 -->
  <div id="p5-root"></div>

  <!-- UI 层容器 -->
  <div id="ui-layer">
    <!-- 1. 主菜单 (默认显示) -->
    <div id="scene-home" class="ui-scene">...</div>

    <!-- 2. 联机大厅 (默认隐藏) -->
    <div id="scene-lobby" class="ui-scene fullscreen">...</div>

    <!-- 3. 战斗 HUD (仅战斗时显示) -->
    <div id="scene-hud" class="ui-scene overlay">
       <!-- 仅包含摇杆、暂停键、核心状态 -->
    </div>
    
    <!-- 4. 暂停菜单 (模态) -->
    <div id="modal-pause" class="ui-modal">...</div>
  </div>
</div>
```

### 3.3 设置页形态（权威约束）

- 设置页必须采用**独立面板**（Overlay + 固定高度 Card），不再嵌入开始菜单面板。
- 设置交互模型为**立即生效**（不允许草稿层与“应用设置”按钮）；dirty 仅表示“与默认值不同”。
- 权威文档：
  - `规划01/平台与设置/设置页UI设计-v1.md`
  - `规划01/平台与设置/设置系统设计.md`

### 3.3 样式类 (CSS)
- **`.ui-scene`**：绝对定位，全屏。
- **`.ui-menu-vertical`**：左侧竖排 Flex 布局，背景模糊（`backdrop-filter: blur`）。
- **`.hud-minimal`**：仅保留关键信息的透明层。

## 4. 迁移步骤
1. **重构 HTML 结构**：在 `createUI` 中建立新的 DOM 层级。
2. **拆分 CSS**：为 Home、Lobby、HUD 编写独立的 CSS 模块/类。
3. **绑定事件**：将原有的按钮事件重新绑定到新 UI 元素。
4. **移除旧逻辑**：删除 `topbar` 相关的显示逻辑，删除 HUD 上的模式切换逻辑。
