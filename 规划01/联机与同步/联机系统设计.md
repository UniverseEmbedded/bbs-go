# 联机系统设计

本文档定义联机系统的核心设计，包括网络协议、同步规则、客户端驱动模式等。

---

## 核心约束

| 约束项 | 值 |
|--------|-----|
| 服务端帧率 | 60 TPS，固定步长 |
| 快照下发频率 | 60 Hz（每 tick 一次） |
| 客户端插值窗口 | 33ms（约2 tick） |
| 传输格式 | JSON文本帧（第一版），后续可换msgpack |
| 数值类型 | f64（与TS对齐） |
| 传输协议 | WebSocket |

---

## 网络协议定义

协议硬规格见 [联机协议规格v2.md](./联机协议规格v2.md)。

本文档只描述“系统层面的关键消息与流程”。

### 关键消息（v2）

- 握手：`hello/hello_ack`
- 房间目录：`list_rooms/rooms/rooms_update`
- 房间管理（仅主机）：`create_room/rename_room/close_room`
- 加入房间：`join_room/join_room_ack/join_room_reject`（识别码按房间独立）
- 房间内同步（按 roomId 路由）：`room_state/input_state/snapshot/rematch_vote/rematch_state`
- 心跳：`ping/pong`（用于 RTT 计算与超时断开）

## Tick与输入规则

### 输入模型（状态同步）

- 客户端持续发送“当前输入电平态”（建议 60Hz）：
  - `{t:"input_state", seq, player, input}`
  - `seq` 为客户端单调递增序号，用于去重与乱序丢弃。
- 服务端为每个玩家维护“最后一次输入态”，每 tick 直接复用该输入推进后端。
- 兼容：`input(tick, ...)` 仍可用，但服务端会忽略 `tick`，按状态输入处理。

输入字段要点：

- `moveX/moveY`：移动方向输入。
- `aimX`：水平瞄准输入（用于长弓蓄力阶段 aimAngle 微调）。通常可令 `aimX === moveX`。

### 服务端输入处理

- 服务端收到输入时：
  - 校验 player 槽位（p1/p2 不可互串）
  - 按 `seq` 去重（丢弃旧序号）
  - 更新该玩家的“最后输入态”
- 服务端 tick loop 中不会因为某些 tick 缺输入而回退到默认输入（避免蓄力/角度类逻辑被打断）。

### 缺输入策略

| 情况 | 处理 |
|------|------|
| 刚加入尚未发过输入 | 使用默认输入（全0/false） |
| 后续某段时间未再发 | 继续复用“最后输入态” |
| input_state.seq 乱序/重复 | 丢弃旧序号（不回退重算） |

## 快照下发规则

### 下发频率

- 服务端 60 TPS step
- 每 tick（60Hz）广播`{t:"snapshot", tick, snapshot}`
- `snapshot.tick`必须等于消息里的`tick`

### 快照内容

快照结构见 [联机协议规格v2.md](./联机协议规格v2.md) 第 13 节"核心数据结构"。

### 粒子策略

当前实现中，粒子由服务端同步给客户端：

- 服务端发出的 `snapshot.particles` 包含完整粒子数据
- 粒子由服务端 RNG 驱动生成，保证所有客户端看到的粒子效果一致
- 未来如需优化带宽，可改为"客户端本地重建"策略，但需确保 RNG 种子在房间初始化时同步

## 客户端驱动模式

### LocalDriver（单机/本地双人）

现有逻辑不变：
- 读InputSnapshot → backend.step → renderer.render

### NetDriver（联机）

当前实现为“独立权威服务端（duel-server）”：

- 客户端只发送输入态（input_state）与控制消息（hello/join/ping）。
- 服务端负责：tick loop、维护每玩家最后输入态、推进后端、广播快照。
- 客户端负责：插值渲染快照 + 本地重建粒子系统。

## 插值缓冲设计

### InterpBuffer

```ts
class InterpBuffer {
  private buffer: Array<{tick: number, snapshot: BackendSnapshot}>;
  private bufferSize: number = 10;

  push(tick: number, snapshot: BackendSnapshot): void;
  getRenderSnapshot(renderTick: number): BackendSnapshot;
}
```

### 渲染tick计算

- 当前渲染tick = `latestTick - bufferTicks`（推荐 2）

### 插值策略

| 字段 | 是否插值 |
|------|----------|
| 玩家位置 | 是（线性插值） |
| 玩家朝向 | 是（角度插值） |
| 箭位置 | 是 |
| 粒子 | 否（直接使用服务端数据） |
| 游戏状态 | 是（只对 properFrameCount 做平滑推进；kind 仍离散切换） |

### 客户端视角（P2 旋转 180°）

为避免“P2 从画面上方向下打”的反直觉体验，客户端可对 P2 采用本地 180° 旋转视角：

- 渲染：对渲染用快照整体做 180° 旋转，使本机玩家始终在画面下方。
- 输入：P2 发送输入时对坐标系做映射：
  - `moveX/moveY` 取反（位移方向与画面一致）
  - `aimX` 不取反（保证长弓蓄力时左右瞄准与按键一致）

## 连接流程

### 服务端启动

开发阶段可用独立 CLI 服务端形式启动（duel-server），监听 WebSocket 地址供客户端连接。

产品形态（桌面/安卓）目标为端内开服：同进程后台任务启动 WebSocket 服务端，并同时发布 LAN 自动发现（UDP 广播 + mDNS）。端内开服与发现策略见《LAN发现与端内开服设计》。

最小可跑示例（在 `duel-app/src-tauri` 目录下执行）：

```bash
cargo run -p duel-server
```

默认参数（独立 CLI 服务端示例）：

- bind：`0.0.0.0`
- port：`9001`
- seed：`12345`

如果需要显式指定：

```bash
cargo run -p duel-server -- --bind 0.0.0.0 --port 9001 --seed 12345 --log-level info
```

客户端侧通常连接：`ws://127.0.0.1:9001`（同机联调时）。

说明：

- 端内开服为支持同机多开，端口不应固定；推荐自动分配可用端口并在 UI/发现/邀请中展示实际端口。

### 客人加入房间（v2，多房间）

1. 选择一个 Server（发现列表或手动输入 `IP:PORT`/wsUrl）
2. 建立 WebSocket 连接
3. 发送 `hello { protocol: 2 }`
4. 收到 `hello_ack { protocol: 2 }`
5. 发送 `list_rooms`，收到 `rooms`
6. 选择房间与角色，必要时输入房间识别码，发送 `join_room`
7. 收到 `join_room_ack { roomId, you, seed, tick }`
8. 开始发送 `input_state`、接收 `snapshot`（房间内消息按 roomId 路由）

### 对局开始

1. 双方都join成功
2. 服务端进入ready状态
3. 双方按普攻确认准备
4. 服务端进入start（倒计时）
5. 倒计时结束进入play
6. 对局结束后进入result

## 断线处理

| 场景 | 处理 |
|------|------|
| 房主断开 | 服务端关闭，guest收到kick |
| Guest断开 | 服务端释放p2槽位，对局可继续（p2变AI或暂停） |
| 网络抖动 | 心跳超时后断开 |

### 心跳机制

- 客户端每2秒发送`ping`
- 服务端回复`pong`
- 超过10秒无响应视为断开

## 版本兼容

### 协议版本

- `hello`消息包含`protocol`字段
- 当前基线：2（单 Server 多房间）
- 版本不匹配时返回协议错误并断开（细则见协议规格）

### 游戏版本

- `hello`消息包含`client.version`
- 服务端可记录用于调试
- 版本不一致时警告但不拒绝（开发阶段）

## 与现有实现对齐说明

当前实现已迁移到 **v2**（单 Server 多房间），详见 [联机协议规格v2.md](./联机协议规格v2.md)。

### 必须锁死的行为

以下行为必须在实现中保持唯一，避免分叉：

| 行为 | 规格 |
|------|------|
| 插值缓冲不足 | freeze（冻结渲染，保持最后一帧） |
| 心跳间隔 | 2 秒发送 ping |
| 心跳超时 | 10 秒无响应视为断开 |
| 输入 seq | 客户端单调递增，服务端只保留最大 seq |
| 缺输入策略 | 继续复用 last_input，不回退默认值 |
| P2 输入映射 | moveX/moveY 取反，aimX 不变 |

### 客户端网络状态机

客户端网络状态必须遵循唯一的状态转移规则，详见 [客户端网络状态机规格.md](./客户端网络状态机规格.md)。
