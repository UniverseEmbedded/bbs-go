# 客户端网络状态机规格

本文档定义客户端网络状态机，确保断线/重连/回退行为唯一且可预测。

---

## 1. 状态定义

### 1.1 状态列表

| 状态 | 说明 |
|------|------|
| IDLE | 未连接，初始状态 |
| CONNECTING | WebSocket 连接中（含 hello/hello_ack） |
| CONNECTED | 已完成握手，未入房 |
| BROWSING_ROOMS | 已获取房间列表（可刷新/选择房间/Host 管理） |
| JOINING_ROOM | 已发送 join_room，等待 join_room_ack/join_room_reject |
| IN_ROOM | 已加入房间，等待开局 |
| IN_GAME | 对局进行中，持续收发数据 |
| DISCONNECTED | 连接断开，需用户干预 |

### 1.2 并行子系统（非状态）

以下能力不作为“主状态”表达，而是并行运行并向 UI 提供数据：

| 子系统 | 说明 |
|--------|------|
| Discovery | LAN 自动发现：以 mDNS 为主路径（UDP 可选回退），生成“可连接服务器列表” |
| Heartbeat | ping/pong 心跳与 RTT 统计 |
| RoomView | room_state / rematch_state 的 UI 状态聚合（按 roomId 路由） |

### 1.3 状态转移图

```
IDLE ──connect()──> CONNECTING ──hello_ack──> CONNECTED
                         │                         │
                         │<──error/close───────────│
                         │                         │
                         │                 list_rooms()

                         │                         ▼
                         │               BROWSING_ROOMS
                         │                         │
                         │                   join_room()
                         │                         │
                         │              ┌──────────┴──────────┐
                         │              │                     │
                         │      join_room_ack          join_room_reject
                         │              │                     │
                         │              ▼                     │
                         │          IN_ROOM <─────────────────┘
                         │              │
                         │         snapshot(phase=start)
                         │              │
                         │              ▼

                         │              │

```

## 2. 状态转移规则

### 2.1 IDLE → CONNECTING

触发条件：用户点击"连接"按钮

动作：
- 创建 WebSocket 连接
- 设置连接超时定时器（建议 10 秒）
- 停止 Discovery（避免重复广播/浏览带来噪声），若连接失败则恢复

### 2.2 CONNECTING → CONNECTED

触发条件：收到 `hello_ack`

动作：
- 清除连接超时定时器
- 启动心跳定时器（每 2 秒发送 ping）
- 允许用户拉取房间列表（list_rooms）并进入 BROWSING_ROOMS

### 2.3 CONNECTING → DISCONNECTED

触发条件：
- WebSocket onerror
- WebSocket onclose
- 连接超时
- 收到 `error` 消息

动作：
- 清除连接超时定时器
- 记录断开原因
- 通知 UI 显示错误

### 2.4 CONNECTED → BROWSING_ROOMS

触发条件：收到 `hello_ack` 后发送 `list_rooms` 并成功收到 `rooms`

动作：
- 拉取房间列表并渲染（可后续刷新）

### 2.5 BROWSING_ROOMS → JOINING_ROOM

触发条件：用户选择房间与角色，发送 `join_room`

动作：
- 设置 join_room 超时定时器（建议 5 秒）

### 2.6 JOINING_ROOM → IN_ROOM

触发条件：收到 `join_room_ack`

动作：
- 清除 join_room 超时定时器
- 记录 `you`（p1/p2）、`seed`、`tick`、`roomId`
- 初始化插值缓冲
- 通知 UI 进入房间

### 2.7 JOINING_ROOM → BROWSING_ROOMS

触发条件：收到 `join_room_reject`

动作：
- 清除 join_room 超时定时器
- 通知 UI 显示拒绝原因
- 返回房间列表

### 2.8 IN_ROOM → IN_GAME

触发条件：收到 `snapshot` 且 `phase === "start"` 或 `"play"`

动作：
- 初始化游戏渲染
- 开始发送 input_state

### 2.9 IN_GAME → IN_ROOM

触发条件：收到 `snapshot` 且 `phase === "result"`

动作：
- 显示结算界面
- 停止发送 input_state
- 保留房间状态

### 2.10 任意状态 → DISCONNECTED

触发条件：
- 收到 `kick` 消息
- 收到 `error` 消息（协议错误）
- WebSocket onclose
- 心跳超时（10 秒无响应）

动作：
- 停止心跳定时器
- 清空插值缓冲
- 记录断开原因
- 通知 UI 显示断开状态

## 3. 重连策略（当前）

### 3.1 不支持自动重连

当前阶段，断开后不自动重连：

- 用户需要手动点击"重新连接"
- 重连后需要重新选择槽位
- 不保留对局状态

### 3.2 重连流程

1. 状态回到 IDLE
2. 用户点击"连接"
3. 重新走 CONNECTING → CONNECTED → BROWSING_ROOMS → JOINING_ROOM → IN_ROOM
4. 如果房间槽位已被占用，可能收到 `join_room_reject { reason: "slot_taken" }`

## 4. 插值缓冲管理

### 4.1 InterpBuffer 规格

```ts
interface InterpBufferConfig {
  minBufferSize: number;    // 最小缓冲深度，默认 3
  maxBufferSize: number;    // 最大缓冲深度，默认 10
  interpDelayTicks: number; // 插值延迟 tick 数，默认 2
}
```

### 4.2 缓冲不足策略

当缓冲区快照数量 < minBufferSize 时：

| 策略 | 说明 | v1 选择 |
|------|------|---------|
| freeze | 冻结渲染，保持最后一帧 | ✓ 推荐 |
| snap | 直接显示最新快照 | 可选 |

v1 选择 **freeze** 策略：渲染暂停，等待缓冲恢复。

### 4.3 缓冲溢出策略

当缓冲区快照数量 > maxBufferSize 时：

- 丢弃最旧的快照
- 保持 interpDelayTicks 窗口

### 4.4 渲染 tick 计算

```
renderTick = latestSnapshot.tick - interpDelayTicks
```

## 5. 心跳管理

### 5.1 心跳参数

| 参数 | 值 |
|------|-----|
| ping 间隔 | 2 秒 |
| 超时阈值 | 10 秒 |
| 超时动作 | 断开连接，状态 → DISCONNECTED |

### 5.2 心跳状态

```ts
interface HeartbeatState {
  lastPingTime: number;     // 上次发送 ping 的时间
  lastPongTime: number;     // 上次收到 pong 的时间
  pendingPings: number;     // 等待响应的 ping 数量
}
```

### 5.3 心跳逻辑

每 2 秒：
1. 如果 pendingPings > 0，检查是否超时
2. 发送 ping，pendingPings++
3. 收到 pong 时，pendingPings--

超时判断：
- 如果 `now - lastPongTime > 10000`，视为断开

## 6. 输入发送策略

### 6.1 发送时机

- 状态为 IN_GAME 时持续发送
- 建议频率：60Hz（与渲染帧同步）
- 每次发送 seq++

### 6.2 输入来源

| 平台 | 输入来源 |
|------|----------|
| 桌面 | 键盘/手柄 |
| 移动端 | 触控摇杆 |
| VR | VR 控制器 |

所有输入归一化为 PlayerInput 格式。

### 6.3 P2 输入映射

P2 发送前对 moveX/moveY 取反，aimX 不变。

## 7. UI 状态映射

### 7.1 状态 → UI 显示

| 网络状态 | UI 显示 |
|----------|---------|
| IDLE | 显示发现列表 + 手动 wsUrl，"连接"按钮可用 |
| CONNECTING | 显示"连接中..."，按钮禁用 |
| CONNECTED | 准备进入房间列表（自动拉取 rooms） |
| BROWSING_ROOMS | 显示房间列表（刷新/选择房间/输入识别码/加入） |
| JOINING_ROOM | 显示"加入中..."，按钮禁用 |
| IN_ROOM | 显示房间占槽、对手状态、RTT、结算后的 rematch 双确认 |
| IN_GAME | 游戏画面 + RTT（可选） |
| DISCONNECTED | 显示断开原因，"重新连接"按钮 |

### 7.2 错误信息映射

| 原因 | UI 提示 |
|------|---------|
| room_full | "房间已满" |
| slot_taken | "该位置已被占用，请选择另一位置" |
| bad_protocol | "版本不兼容，请更新客户端" |
| host_disconnected | "房主已断开连接" |
| heartbeat_timeout | "网络连接超时" |
| bad_room_code | "识别码错误，请重试" |
| rate_limited | "请稍候再试" |
| not_host | "只有房主可以创建房间" |

## 8. LAN 自动发现（Discovery）

本节定义客户端侧发现列表的最小行为，具体协议参见《LAN发现与端内开服设计》。多房间的房间目录与加入流程参见《联机协议规格v2》。

### 8.1 启动与停止

- 在 IDLE 状态默认启动 Discovery（桌面/安卓端）
- 当用户进入 CONNECTING 时停止 Discovery
- 当用户回到 IDLE 或连接失败进入 DISCONNECTED 时恢复 Discovery

### 8.2 数据输出（供 UI）

Discovery 产生 `DiscoveredHost[]`：

- `serverName`
- `wsUrl`
- `protocol`（用于过滤不兼容条目）
- `source`（mDNS/udp/both，仅诊断用）
- `lastSeenMs`

UI 必须保留“手填 wsUrl”作为兜底路径。

## 9. 房间 UI 聚合（RoomView）

### 9.1 room_state 驱动的占槽显示

UI 对 P1/P2 的展示以服务端推送的 `room_state` 为权威来源：

- `p1.joined` / `p2.joined`
- `p1.name` / `p2.name`
- `codeRequired`

### 9.2 RTT 显示

- RTT 由 ping/pong 计算
- UI 展示使用平滑值（建议 EMA），同时保留原始值用于调试

### 9.3 rematch 双确认（结算后）

- 当收到 `snapshot.phase === "result"` 时，UI 展示“再来一局”入口
- 点击后发送 `rematch_vote { want: true }`
- UI 通过 `rematch_state.want.p1/p2` 展示双方确认进度
- 只能在 result 阶段投票，其他阶段入口不可用

## 10. 调试面板

### 10.1 显示内容

- 当前状态
- RTT（毫秒）
- 服务端 tick
- 本地 renderTick
- 插值缓冲深度
- 丢包统计（可选）

### 10.2 延迟注入

调试时可配置：

| 参数 | 范围 |
|------|------|
| 方向 | 入站/出站/双向 |
| 基础延迟 | 0-500ms |
| 抖动 | 0-500ms |
| 丢包率 | 0-50% |
| 乱序率 | 0-50% |
| 重复率 | 0-50% |
| 带宽上限 | 0-∞（0 表示不限制） |
