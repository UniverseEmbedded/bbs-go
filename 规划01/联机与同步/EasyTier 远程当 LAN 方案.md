# EasyTier 远程当 LAN 方案

本方案将 EasyTier 用作“远程当局域网（Overlay LAN）”的基础设施：让异地设备进入同一虚拟局域网，然后沿用本项目现有的 LAN 联机机制（房主开服 + 客户端通过 `wsUrl` 直连 Rust `duel-server`）。

本方案属于“远程联机阶段”的组成部分，但不与“游戏协议层 P2P（客户端互传输入/状态、无权威服）”混淆。

---

## 目标与非目标

### 目标

- 让两台异地设备在不改动对局网络协议的前提下完成对战闭环
- 将“公网打洞/中继”的复杂度下沉到 EasyTier，并提供可解释、可切换、可停用的入口节点策略
- 在 UI 明示第三方节点来源与可选项，保持开放透明的开源态度

### 非目标

- 不在本阶段实现“纯浏览器 Web 内网穿透/ICE/TURN”方案
- 不将本方案等同于“公开服务器房间大厅/匹配系统”
- 不要求 UDP 广播 / mDNS 发现跨 VPN 可用（多数情况下不可用）

---

## 架构定位

### 数据面

1. EasyTier 建立 Overlay 网络（虚拟 IP）
2. 房主在本机运行 `duel-server`（权威模拟，WebSocket）
3. 其他玩家通过 `ws://<房主虚拟IP>:<端口>` 直连

### 控制面

- Tauri 端：负责 EasyTier 的启动/停止、状态读取、日志导出、可达地址生成
- Web 端：只提供“连接地址输入/粘贴/选择”，不尝试在浏览器内运行 EasyTier

---

## 入口节点（Public Servers）与开源态度声明

### 默认入口（来自 Terracotta/HMCL 社区实践）

以下入口节点来自 Terracotta（陶瓦联机）项目的默认公共节点列表（见其源码 `src/easytier/publics.rs`），在本项目中作为“默认可选项”提供：

- `tcp://public.easytier.top:11010`
- `tcp://public2.easytier.cn:54321`
- `https://etnode.zkitefly.eu.org/node1`
- `https://etnode.zkitefly.eu.org/node2`

其中 `https://.../node*` 入口将由 EasyTier 的 HTTP connector 在运行时解析为可连接地址（重定向或返回列表）。

### UI 文案与用户选择

- UI 必须清楚告知用户：当前选择的入口节点来自第三方（Terracotta/HMCL 社区节点），并提供：
  - 一键切换为“仅使用自建入口（空列表）”
  - 一键恢复“默认入口列表”
  - 自定义添加/移除入口
- UI 必须提供“停止使用第三方节点”的路径：当用户关闭第三方入口后，仍可通过手动输入 `wsUrl` 进行联机（前提是用户自行解决网络可达性）。

### 异议与沟通

如 HMCL / Terracotta / 节点维护者对本项目使用其公开入口节点存在异议，请联系本项目维护者进行沟通。本项目会在合理时间内提供替代入口并停止默认使用相关第三方节点。

---

## 关键前置：可分享的可达地址

要让本方案对用户友好，必须修复/补齐“开服后可分享地址”的链路：

- 房主端必须展示可被对方访问的 `wsUrl`（包括 EasyTier 虚拟网卡对应的 IP）
- 在多网卡环境下必须提供“候选地址列表”供用户选择
- 禁止仅展示 `127.0.0.1` 作为对外分享地址

---

## 流程（用户视角）

### 房主

1. 在“远程联机（EasyTier）”页选择或保持默认入口节点列表
2. 输入网络名/密钥并启动 EasyTier
3. 一键开服（运行 `duel-server`）并显示“可分享连接地址”
4. 复制地址发送给朋友

### 加入者

1. 选择同一网络名/密钥并启动 EasyTier
2. 粘贴房主分享的 `wsUrl` 并连接

---

## 验收标准

- 桌面端与安卓端：两台异地设备可在 EasyTier 网络内完成一局对战
- 节点入口不可用时：UI 能明确提示失败原因，并可切换入口或关闭第三方入口
- 能一键导出 EasyTier 运行日志，用于排障与社区沟通
