# 触控 UI 显示与命中规则

本文档记录触控 UI（摇杆/按钮/LAN 面板）在本项目里的“显示条件”和“命中规则”，用于排查“看起来 UI 消失/失效”的问题。

---

## 1. 总开关：touch-controls class

触控系统的总开关不是某个布尔变量，而是 DOM class：

- `#game-root.touch-controls` 存在时：触控区域可命中、触控控件允许显示
- 不存在时：触控区域不吃 pointer 事件，摇杆/按钮会表现为“不响应”

关键依赖：

| 节点 | 默认行为 | `touch-controls` 生效后 |
|------|----------|--------------------------|
| `#touch-area` | `pointer-events: none` | `pointer-events: auto` |

实现文件（便于定位）：`duel-app/src/styles.css`、`duel-app/src/ui.ts`

---

## 2. 摇杆为何“默认看不见”

摇杆 UI 的显示是事件驱动的：

- `.touch-stick` 默认 `display: none`
- 只有收到 `pointerdown` 并且通过起点区域判定后，才会给 `#joystick`（或 P2 的 `#joystick-p2`）加 `.active`，从而显示摇杆

因此“摇杆不见”的排查顺序应是：

1) `#game-root` 是否带 `touch-controls`
2) `#touch-area` 是否能收到 `pointerdown`
3) `isStickStartAllowed(...)` 是否放行
4) 是否因为 `pointercapture` 丢失导致 move/up 没继续更新

---

## 3. 起点区域规则：isStickStartAllowed

摇杆并不是在全屏任意位置都允许起手，存在“允许区域”：

- 横屏：通常限制在左半屏，避免与右侧按钮冲突
- 竖屏：历史上容易写成“必须在按钮区上方”，会导致左下起摇杆失败

该规则的目的是防止：

- 右侧按钮区域误触触发摇杆
- LAN 面板/帮助面板等遮罩层被底层触控抢走

排查时建议优先把现象分类：

| 现象 | 更可能原因 |
|------|------------|
| 摇杆完全不起 | `touch-controls` 未启用或起点区域被拒绝 |
| 摇杆能起但会“断” | pointer capture 被抢、系统手势打断、页面失焦 |
| 只有竖屏不起 | 竖屏分支的起点规则过严或安全区计算影响控件位置 |

---

## 4. 本地双人竖屏：P2 对坐的输入与命中

本地双人竖屏的 P2 对坐包含两类变换，容易混淆：

1) 显示层变换：`#p2-layer` 做 180° 旋转（只影响视觉位置）
2) 输入层变换：为了让 P2 的摇杆手感正确，可能会对屏幕坐标或摇杆输出做一次镜像/取反

重要提示：

- CSS transform 会影响命中测试的“视觉位置”，但不会自动替你定义“左右语义应该怎样”
- 如果同时在“屏幕坐标层镜像”和“摇杆输出取反”做处理，要明确它们是互补还是叠加，否则会出现翻两次

关联文档：
- 《输入与视角映射总览》：列出本项目当前各处翻转发生点

## 5. 安全区与遮罩层

移动端存在 `safe-area-inset`，且双人竖屏的 P2 视觉上上下互换：

- 控件布局可能使用 `--safe-top/--safe-bottom`
- P2 倒置后若仍沿用同一安全区变量，会出现控件“看得见但点不到/被遮罩覆盖”的错觉

排查建议：

1) 先确认控件 DOM 是否真的显示（`display`/`visibility`）
2) 再确认是否 `pointer-events: none`
3) 最后确认是否被更高 z-index 的遮罩层挡住
