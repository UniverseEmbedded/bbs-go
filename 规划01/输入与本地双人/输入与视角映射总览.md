# 输入与视角映射总览

本文档把“输入方向/视角翻转/透视映射”涉及的关键实现点集中到一页，目的是：让后续修改不再出现“桌面端对了但移动端坏了 / 反之亦然”。

---

## 1. 术语与变量

### 1.1 坐标/语义层

本项目里同一件事会在多层出现，必须区分：

| 层 | 典型来源 | 典型数据 | 说明 |
|----|----------|----------|------|
| 屏幕坐标 | `PointerEvent.clientX/clientY` | 像素 | 与设备、旋转、CSS transform 强相关 |
| UI 输入语义 | 摇杆/按键/触控手势 | `moveX/moveY/aimX` | 希望表达“向左/向右”的主观输入 |
| 世界/模拟语义 | 后端 tick 逻辑 | `aimAngle`、速度等 | 固定 tick，协议/回放依赖它 |

### 1.2 关键输入字段

| 字段 | 范围 | 在本项目的实际含义 |
|------|------|--------------------|
| moveX/moveY | [-1, 1] | 平移方向输入 |
| aimX | [-1, 1] | 蓄力阶段对 `aimAngle` 的微调输入（角速度方向） |

注意：`aimX` 不是“瞄准向量的 X 分量”。更详细定义见《联机协议规格 v1 / 6.2.1》。

## 2. 变换发生点清单（按代码路径）

### 2.1 触控输入（UI 层）

| 目的 | 发生点 | 说明 |
|------|--------|------|
| 控制触控系统是否启用 | `#game-root.touch-controls` | 影响 `#touch-area` 的命中（pointer-events） |
| 双人竖屏 P2 对坐 | `#p2-layer` 旋转 180° | 只影响“显示坐标”，不自动修正输入语义 |
| 触控摇杆读取 | `readStickMove(stick, invert)` | 支持对输出向量做一次取反 |
| 双人模式 P2 摇杆追踪 | pointer 事件里对 P2 做 `w-x / h-y` | 这是屏幕坐标层的镜像处理 |

实现文件（便于定位）：`duel-app/src/ui.ts`、`duel-app/src/styles.css`

### 2.2 LAN 联机（网络层 + 渲染层）

| 目的 | 发生点 | 说明 |
|------|--------|------|
| P2 上行输入映射 | `mapInputForNet(role, input)` | 仅影响发往服务端的输入语义 |
| P2 客户端渲染透视 | `applyPerspective(role, snapshot)` | 仅影响显示坐标：对快照做 180° 旋转 |

实现文件（便于定位）：`duel-app/src/net/perspective.ts`

## 3. 场景对照（哪些翻转是“应该发生的”）

### 3.1 桌面单人 / 桌面本地双人（共享视角）

- 视角：不做 P2 透视旋转
- 输入：键盘两套键位分别生成 P1/P2 的 `moveX/moveY/aimX`

### 3.2 移动单人（触控）

- 视角：不做 P2 透视旋转
- 输入：摇杆输出 `moveX/moveY`；`aimX` 通常来源于水平输入（当前实现为复用 moveX）

### 3.3 移动本地双人竖屏（上下对坐）

- 显示：P2 的 UI 层会旋转 180°（`#p2-layer`）
- 输入：P2 的触控输入通常会同时经历
  1) 屏幕坐标镜像（`w-x/h-y`）
  2) 摇杆输出取反（`invert=true`）
  3) `aimX` 的生成策略（当前实现倾向于复用水平输入）

这一场景的风险点：同一条“左右”可能在多个层被取反，容易出现“翻两次又回去了”或“只翻了移动没翻瞄准”。

### 3.4 LAN 联机（P2 视角）

- 显示：P2 客户端对快照整体做 180° 旋转（`applyPerspective("p2", snapshot)`）
- 输入：P2 上行只做 `moveX/moveY` 的取反，`aimX` 不取反（详见《联机协议规格 v1 / 10.2》）

这一场景的风险点：把渲染透视当成输入透视，导致额外对 `aimX` 取反。

## 4. 常见误读与排障入口

### 4.1 “摇杆不见/不响应”优先查什么

1) `#game-root` 是否带 `touch-controls`（否则 `#touch-area` 不吃 pointer）
2) 是否确实收到了 `pointerdown`（摇杆 `.active` 只在按下时出现）
3) 是否被 `isStickStartAllowed()` 规则挡住（起点区域过严时会像“摇杆失效”）

### 4.2 “P2 蓄力左右反”优先查什么

1) 这是 LAN 联机还是本地双人竖屏（两条链不同）
2) `aimX` 的来源是否被当成 `moveX` 的派生（派生关系会把移动修复顺带带入瞄准）
3) 是否在多个层对同一语义重复取反（UI 层 + 网络层 + 渲染层）
