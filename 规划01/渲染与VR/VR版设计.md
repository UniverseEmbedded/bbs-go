# VR版设计

本文档定义VR版的核心设计，目标是：**坐姿/躺姿友好、最小空间需求、与非VR共用同一套对战规则与联机体系**。

---

## 核心定位

VR版不是独立的VR体感射击游戏，而是"把VR当成另一种输入/视角设备"。

**关键约束：**

- 跨端联机必须成立：至少VR能和非VR对战
- 空间与安全优先：坐/躺就能玩，避免需要走动或大范围挥舞
- 输入语义稳定：普攻/大招在所有端都同语义；VR只是换输入映射
- 复杂度分层：基础VR（对非VR）保持简单；VR-only才开更多自由度

---

## 默认姿态：坐在椅子上/躺在床上都能玩

- 不要求腾出VR空间
- 不要求玩家在现实中移动
- 也更安全（避免撞墙/摔倒）
- 同时也降低眩晕风险：游戏内不强迫玩家做"身体位移"

---

## 玩家抽象：坐在立方体小飞船里

这是一个关键抽象：把VR体验从"身体"转移到"载具/座舱"。

- VR里玩家的"位置/移动"是飞船运动，而不是人走动
- 这让你能把VR与非VR共享同一套战斗逻辑（都是飞船在二维/三维空间里运动与射击）

---

## 视角模式选择

### 上帝视角（默认推荐）

**场景设定：**

- 两个玩家在VR世界中面对面看着一个立方体水箱一样的东西
- 里面有两个惯性飞船

**视角选择：**

1. **顶视角/斜45度**（最像街机弹幕）：读弹最好，最不晕
2. **"跟随摄像机的第三人称"**（更像载具对战）：更有速度感，但要限制摄像机加速度/晃动

**推荐：斜45度**——既保留空间感，又不牺牲可读性。

**优势：**

- 大幅降低晕退 → D1留存会明显更好
- "惯性滑行"更容易被理解：玩家更快把它理解为物理运动而不是"我人被甩"
- 躲弹快感更稳定、更可控
- 参照物可见性更好：玩家能同时看到自己和敌人的位置关系

### 第一人称载具视角（高级模式）

玩家坐在飞船座舱内，以第一人称视角进行对战。

**适用人群：** 硬核玩家，追求更强沉浸感

**问题：**

- 玩家身体没动、视觉在高速运动（尤其是加速、侧移、上下起伏）
- 这类视觉-前庭冲突天生比站立走路还容易晕
- 需要标注"可能引起不适"警告

## 输入映射

**详细方案见 [VR参照物与飞控设计.md](./VR参照物与飞控设计.md)**

### 方案概述

VR飞控方案需要兼顾直觉性、舒适度和竞技深度。经过分析，推荐以下方案优先级：

1. **牵引绳拖拽方案（默认）**：最符合VR直觉，玩家"抓住"虚拟牵引绳拖拽飞船移动
2. **指向+推力方案（备选）**：手柄指向方向+扳机推力，适合习惯飞行模拟的玩家
3. **虚拟摇杆方案**：传统摇杆映射，适合从桌面端迁移的玩家
4. **半自动轨道闪避方案**：降低操作门槛，适合新手

### 攻击输入

| 输入 | 功能 |
|------|------|
| 左扳机 | 普攻 |
| 右扳机 | 大招 |

攻击输入在所有方案中保持一致，确保跨端对战公平性。

---

## VR vs VR 的额外自由度

只有当"VR vs VR"时，才额外启用更复杂的自由度：

- 启用 **左右手柄同时控制 + Y轴（VR的上下轴）**
- 引入 **"大招Pro"**：
  - 它发射的是"线"而不是"点"
  - 意味着攻击从点状命中变成"在一个面上完成打击"（更像扫射/切割/光束成面）

这让VR-only的对战有更高上限和更VR的表现力，但不强迫VR去兼容非VR的输入上限。

## 视角锁定策略

### 不要锁头（不要强制视角永远看敌人）

强制旋转玩家视角是VR最容易不适的来源之一（尤其在躺着时更糟）。一旦玩家真的想扭头（看UI、看侧边提示、躺床调整姿势），系统又把视角拽回去，会造成"头和眼所感知的不一致" → 眩晕/烦躁。

### 要锁定的是操控与战斗参考框架

**三层锁定：**

| 层级 | 说明 |
|------|------|
| 层1：锁定控制坐标系（必须有） | 左手WASD控制"上下左右（切向平面）"，右手RF控制"前后（距离）"，这套控制始终以"锁定目标在前方"的坐标系来解释 |
| 层2：锁定瞄准/射击参考（建议有） | 准星固定在"锁定框架的前方"（不是头部中心）；头转到侧面时，准星变成HUD指示（边缘箭头+距离/方位角） |
| 层3：温和的视角回正辅助（可选） | 当玩家持续偏头超过某阈值（例如 > 60°）并且仍在战斗时，系统给一个可控的"回正" |

**默认行为：**

- **允许自由扭头**（头部纯观察）
- **操控/射击仍按锁定框架**（不受扭头影响）
- 目标脱离视野时显示HUD指向（箭头+距离）

## 参照物设计

### 核心问题

敌方移动对操作影响不大，因为敌方不会瞬移，只是加减速。真正要解决的是**空间定向与距离感**——解决办法是给玩家更多稳定参照物。

### 参照物体系

#### 1) 敌方尾迹（速度方向线索）

- 解决：敌方在视野里移动时，"它往哪儿去、速度大概多少"
- 好处：即使敌方不在中心点，尾迹也能让你一眼看出运动趋势

#### 2) 距离 + 经纬度（相对位置线索）

- 解决：你现在是"更近了还是更远了？偏左还是偏右？在上还是在下？"
- "经纬度线条"：以敌方方向为"极轴"，在锁定参考系上叠加类似球坐标的角度提示（方位角/俯仰角）

#### 3) 三方向横竖直线条（姿态/航迹线索）

- 解决：玩家自己在做环绕运动时，会不会"转着转着不知道自己绕到哪里了"
- 三个方向（水平/垂直/纵深）的线条或网格，让玩家随时知道自己在怎么绕、怎么拉、怎么偏航

### 参照物设计要点

**参照物要稳定：**

- 如果线条/网格本身也跟着镜头乱飘、或透明度/闪烁频繁变化，就会变成新的视觉负担
- 极简风格最怕"参照物变噪声"

**信息层级要清晰：**

- 第一层：敌方（实体+可能的尾迹）
- 第二层：距离/角度（最关键的数字与简洁刻度）
- 第三层：环境网格/三轴线（提供"我在绕"的背景感，但不能抢戏）

## 眩晕控制策略

### 眩晕触发器

| 触发器 | 问题 | 解法 |
|--------|------|------|
| 突然加速/减速 | 最大元凶 | 缓启动/缓刹车，短冲刺要有冷却 |
| 侧向平移与上下WS | 很晕 | 给稳定参照系（驾驶舱框架/HUD边框） |
| 画面延迟/抖动/掉帧 | VR晕的放大器 | 目标稳定帧率，不用镜头抖动制造刺激 |

### 用"FPS肾上腺素"覆盖不适

**层1：威胁与压迫（不靠镜头）：**

- "被锁定警报"音色
- 方向性子弹掠过声
- 护盾濒临破碎的裂纹UI
- 呼吸声/心跳声随血量变化

**层2：命中与杀戮节奏：**

- 命中确认：清脆"叮"+ 低频"咚"
- 连击递增音阶
- 击杀瞬间的短时间膨胀感

**层3：决策密度：**

- 普攻有2–3种"箭型/弹型"可切换
- 大招要可读、可反制
- 让玩家"脑子忙、手忙"，镜头别忙

### 舒适度开关策略

在第一局开始前给一个3秒的极简选择：

- **舒适**：更强的驾驶舱框架/更强的边缘遮罩/更慢的加速度
- **竞技**：更弱遮罩/更快响应/更少UI干扰

默认选"舒适"，并允许随时一键切换。

## 回正机制

### 战斗中校准（不暂停、不离开对局）

**Recenter Forward（必做）：**一键把"锁定前方"对齐到当前舒适朝向（只取yaw）。

**技术实现：**

- 使用 `local` 或 `local-floor` 作为基础参考空间
- 用 `XRReferenceSpace.getOffsetReferenceSpace()` 创建"回正后的新空间"
- 用 three.js `WebXRManager.setReferenceSpace()` 应用它

### 回正方式：缓动 vs 瞬时

**推荐：缓动"世界/参考系"，但不动头部**

- 在 200–400ms 内，分多帧逐步更新一个"旋转偏移角度"
- 每帧重新生成一个 offset reference space 并 setReferenceSpace
- 玩家头部姿态依旧来自追踪数据，不会被"拽头"，只是世界相对头部慢慢转回正

**推荐缓动参数：**

- 时长：0.25s～0.4s（再长会让人觉得"世界在漂"）
- 曲线：ease-out（前快后慢），避免尾段一直转
- 角度阈值：如果需要回正的角度很大（比如 > 90°），建议分段或直接提示玩家先手动转头再回正

**交互建议：**

- 短按：瞬时回正（竞技/紧急）
- 长按：缓动回正（默认推荐）

### Roll 模式（躺床用户）

侧躺时，玩家头部会有明显roll。你有两种选择：

- **选项1：真实反映roll（默认WebXR行为）** - 玩家侧着头，世界也侧着看——这在"躺着玩"时反而是自然的
- **选项2：提供"水平锁定（Horizon Lock / Roll Suppress）"开关** - 把渲染相机的姿态做"去roll"：保留yaw/pitch，但把roll归零，让画面永远是"水平的"

**建议：默认选项1（尊重头部姿态），但在设置里给选项2。**

## 实现选择

### 方案A：每帧更新 offset reference space（更"正统"）

- 优点：语义最正确，是真正改变XR空间基准
- 缺点：每帧 `setReferenceSpace` 可能在某些实现上不是最理想

### 方案B：不动reference space，只缓动场景/座舱的"根节点"

- 做法：保持XR reference space不变；把整个"战斗框架/座舱世界"挂在一个root group下，对这个group做缓动旋转
- 优点：简单、可控、不会频繁setReferenceSpace；而且更贴近玩法——你要对齐的是"锁定框架"，不是物理空间
- 缺点：如果未来有"真实世界对齐"的需求（比如AR或room-scale），这种方式需要更谨慎

**推荐：方案B**，因为你回正的目标是"让敌人在你前方参考里"，而不是"重置物理追踪空间"。

## 第一版胜利条件

1. 新手戴上头显30秒内能明白怎么开枪、怎么防御
2. 玩10局不晕、手不累（可持续性）
3. 一局结束立刻想再来（爽、节奏快）
4. 观战/录屏很好看（传播）
