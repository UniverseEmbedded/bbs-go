# 渲染迁移计划（p5 → PixiJS → three.js + Troika）

本文档定义从 p5.js 渲染逐步迁移到 PixiJS 2D 渲染端，并最终迁移到 three.js + Troika Text 的工程切片计划。

说明：当前仓库已具备 p5/Pixi/three 多渲染后端的代码落地；但当前 three 渲染器为占位符实现（Canvas2D → CanvasTexture），必须替换为 three.js 原生渲染（WebGL）并在同一版本内接入 Troika Text。实现方案见 [Three渲染器原生实现方案（CPU几何+Troika）.md](./Three%E6%B8%B2%E6%9F%93%E5%99%A8%E5%8E%9F%E7%94%9F%E5%AE%9E%E7%8E%B0%E6%96%B9%E6%A1%88%EF%BC%88CPU%E5%87%A0%E4%BD%95%2BTroika%EF%BC%89.md)。

---

## 1. 迁移目标

| 目标 | 说明 |
|------|------|
| 性能 | 提升渲染效率，支持低端设备 |
| 3D 能力 | 为 VR 和 3D 效果打基础 |
| 文本渲染 | 使用 Troika Text 解决中文渲染问题 |
| 跨平台 | 统一桌面/移动/VR 的渲染层 |

---

## 2. 迁移原则

### 2.1 不动核心

- Backend 逻辑完全不变
- BackendSnapshot 结构不变
- 输入系统不变

### 2.2 渐进式迁移

- 先实现最小垂直切片
- 保持 p5 / PixiJS / three 可切换
- 逐步替换功能

### 2.3 验证优先

- 每个切片都要有验收标准
- 视觉对比测试（目标：肉眼无差别）
- 性能基准测试

---

## 3. 最小垂直切片

本节按三个阶段组织：

- Phase 1：p5 → PixiJS（2D 性能渲染端，保留 p5 维护）
- Phase 2：PixiJS → three.js（为 3D/VR 打基础）
- Phase 3：three.js + Troika Text（统一文本渲染）

### 3.1 切片 0：渲染抽象层

**目标**：抽象出最小绘图 API，让后端快照渲染可由不同渲染器实现（p5 / Pixi / three）。

**任务**：
- 抽象 `line/rect/ellipse/arc/text/measureText` 与 transform 栈
- p5 适配实现（作为基准，保证行为不变）

**验收**：
- 保持现有视觉与交互不变
- 后续渲染器切换仅替换实现层

### 3.2 切片 1：PixiJS 环境搭建（Phase 1）

**目标**：PixiJS 场景能渲染出来，并复刻现有内部坐标系与缩放策略。

**任务**：
- 创建 Pixi Application/Stage 并挂载到现有容器
- 复刻现有 resize/scale 逻辑

**验收**：
- 空白 Pixi 画布可显示
- 控制台无错误

### 3.3 切片 2：PixiJS 玩家与箭矢（Phase 1）

**目标**：玩家与箭矢在 Pixi 下达到肉眼无差别。

**任务**：
- 使用 `PIXI.Graphics` 实现玩家/箭矢
- 对齐线宽、线帽、旋转、对齐

**验收**：
- 玩家位置、旋转与 p5 版本肉眼一致
- 箭矢轨迹与 p5 版本肉眼一致

### 3.4 切片 3：PixiJS 文本与 HUD（Phase 1）

**目标**：文本渲染与度量行为稳定，并与字体规范一致。

**任务**：
- 统一引用字体规范：MapleMono 全文本
- 对齐倒计时、提示文本的布局与宽度测量

**验收**：
- 中文/英文文本显示一致，文本宽度测量导致的布局不抖动

### 3.5 切片 4：PixiJS 粒子与效果（Phase 1）

**目标**：粒子与特效达到肉眼无差别。

**任务**：
- 复刻背景线、粒子、震动等效果

**验收**：
- 观感与 p5 版本肉眼无差别

### 3.6 切片 5：完整切换（Phase 1）

**目标**：可在 p5 与 PixiJS 之间切换，保留 p5 维护路径。

**任务**：
- 添加渲染器切换开关（debug/URL 参数）
- 保留 p5 路径作为回退与对照

**验收**：
- 切换无明显卡顿
- 所有功能正常

### 3.7 切片 6：three.js 环境搭建（Phase 2）

**目标**：three.js 场景能渲染出来

**任务**：
- 确认 three 依赖与版本（仓库已引入）
- 创建基础 Scene、Camera、Renderer
- 实现 requestAnimationFrame 循环
- 与现有 Backend 解耦
  - Three 渲染器不得使用 CanvasTexture 占位方案
  - 本阶段必须按“CPU 生成几何”的方式落地粗线/圆弧等 2D 图元

**验收**：
- 空白 three 场景能显示
- 控制台无错误

### 3.8 切片 7：玩家渲染（Phase 2）

**目标**：渲染 P1/P2 玩家

**任务**：
- 创建 PlayerMesh（三角形/多边形）
- 从 BackendSnapshot 读取位置/角度
- 实现每帧更新

**验收**：
- 玩家位置与 p5 版本一致
- 玩家旋转正确

### 3.9 切片 8：箭矢渲染（Phase 2）

**目标**：渲染箭矢

**任务**：
- 创建 ArrowMesh
- 处理箭矢生命周期
- 实现轨迹/尾迹效果

**验收**：
- 箭矢飞行轨迹正确
- 碰撞后消失

### 3.10 切片 9：HUD 文本（Phase 3）

**目标**：使用 Troika Text 渲染文本

**任务**：
- 安装 troika-three-text
- 配置字体（以 [字体与样式规范（MapleMono）.md](../平台与设置/%E5%AD%97%E4%BD%93%E4%B8%8E%E6%A0%B7%E5%BC%8F%E8%A7%84%E8%8C%83%EF%BC%88MapleMono%EF%BC%89.md) 为准）
- 渲染 HP、Q 值、倒计时

**验收**：
- 中文显示正确
- 文本位置与 p5 版本一致

### 3.5 切片 4：粒子系统

**目标**：three.js 粒子

**任务**：
- 实现尾迹粒子
- 实现碰撞粒子
- 实现击杀爆炸效果

**验收**：
- 粒子效果与 p5 版本视觉一致

### 3.6 切片 5：完整切换

**目标**：可在 p5 和 three 之间切换

**任务**：
- 实现渲染器抽象层
- 添加切换开关
- 完整功能对齐

**验收**：
- 切换无卡顿
- 所有功能正常

## 4. 坐标系与相机策略

### 4.1 坐标系

| 项目 | p5 | three.js |
|------|-----|----------|
| 原点 | 左上（内部坐标） | 左上（内部坐标） |
| Y 轴 | 向下为正 | 向下为正 |
| 单位 | 内部坐标单位 | 内部坐标单位 |

### 4.2 转换规则

```ts
// three 渲染器使用正交相机，并通过根节点把坐标系对齐到 p5（Y 向下）
const camera = new THREE.OrthographicCamera(0, SIDE, SIDE, 0, 0.1, 100);
camera.position.z = 10;

const screenRoot = new THREE.Group();
screenRoot.scale.y = -1;
screenRoot.position.y = SIDE;
scene.add(screenRoot);
```

## 8. 风险与对策

| 风险 | 对策 |
|------|------|
| 中文渲染模糊 | 使用 Troika Text + 高质量字体 |
| 移动端性能差 | 降低粒子数量、简化材质 |
| VR 晕动症 | 默认上帝视角、限制移动速度 |
| 迁移周期长 | 保持 p5 可用，渐进切换 |
